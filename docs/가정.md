# 만들면서 정한 가정

개발기획안 15장과 완성 프롬프트에 정해지지 않았거나 서로 달랐던 것을 아래처럼 정했다. (2026-11-11, 완성 프롬프트 v1.13로 다시 만들 때)

1. **서술형 총점과 T-31.** 개발기획안 11.1의 T-31 기대값은 "6점"(AI 총점 6.5의 반올림)이지만, v1.12 규칙은 "총점 = 잘라 낸 루브릭 항목 점수의 합"이다. 항목 수가 맞으면 항목 합(예: [2, 0, 1, 0] → 3점), 항목 수가 다르면 AI 총점을 0~10으로 잘라 반올림(6.5 → 6)하는 것으로 테스트했다.
2. **자동 보완 설명 "상위 3개".** 우선순위 표의 위에서 3개를 이해 상태와 상관없이 고른다(개념이 적어 '앎'이 3위 안에 들면 그 개념도 설명한다).
3. **강의 순서가 같은 쪽인 개념.** 본문에 처음 나오는 쪽이 같으면 개념 추출 결과의 순서를 따른다.
4. **근거 쪽 8쪽 고르기.** 그 개념의 본문 쪽(메타 아닌 쪽)을 먼저, 모자라면 메타 쪽을 더해 최대 8쪽.
5. **교수님 말(요약 노트·화면).** 감점 유형(다음에 다룸·가볍게 넘어감)은 빼고, 강한 것부터 같은 문장은 한 번만 3개.
6. **녹음 받아쓰기.** 녹음 파일을 디스크에 쓰지 않고 바이트로 바로 OpenAI 전사 API에 보낸다(임시 파일을 만들지 않으므로 지울 것도 없다).
7. **결과 저장·불러오기(T-67)** 는 "시간이 남으면" 항목이라 이번에는 만들지 않았다.
8. **스크린샷.** 이번 제작에서는 찍지 못했다(브라우저 창이 숨겨져 있었다). README에 스크린샷 자리를 두지 않는다.
9. **결과 예시.** 이 PC에 `.streamlit/secrets.toml`이 없어 `make_example.py`를 실제 AI로 돌리지 못했다. 배포 앱에서 실제 AI로 샘플 한 바퀴를 돌려 내려받은 HTML 2개로 `--from-html` 모드를 써서 만들었다.
12. **실제 AI 측정.** 이 PC에 키가 없어 README의 실제 호출 토큰·시간은 배포 앱 ⑤ 사용량(한 바퀴 합계와 단계별 시간)으로 적었다.
10. **운영진 확인 결과.** 받지 못해 README "제작 경위"에 적지 않았다.
11. **녹음 업로더.** 음성 인식 키(OpenAI)가 없으면 녹음 탭에 안내만 보이고 업로더를 그리지 않는다.
