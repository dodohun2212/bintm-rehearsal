# 만들면서 정한 가정

완성 프롬프트와 개발기획안에 없거나 애매한 것을 이렇게 정했다(개발기획안 15장 기본값, 없으면 가장 단순한 방법).

| 번호 | 정한 것 | 이유 |
|---|---|---|
| G-01 | README "제작 경위"에 운영진 확인 결과를 쓰지 않았다 | 운영진 답을 받지 못했다(U-07 확인 전) |
| G-02 | 결과 예시(`docs/결과_예시/`)는 배포 앱에서 샘플 한 바퀴를 돌려 내려받은 HTML 2개로 만들었다 | 이 PC에 `.streamlit/secrets.toml`이 없어 `scripts/make_example.py`로 실제 AI를 돌릴 수 없었다. 스크립트에 `--from-html` 모드를 두었다 |
| G-03 | README의 "실제 호출 1회 토큰·시간" 자리에 배포 앱 ⑤ 사용량의 한 바퀴 합계와 단계별 시간을 적었다 | 같은 이유로 이 PC에서 한 번 호출을 잴 수 없었다 |
| G-04 | 스크린샷은 넣지 않았다(README에 자리도 두지 않음) | 브라우저 창이 화면에 그려지지 않는 상태라 캡처가 실패했다. 시간이 모자랄 때 가장 먼저 버리는 항목이다 |
| G-05 | 채점한 뒤에는 빠른 진단 토글과 함께 문제 형식 라디오도 잠근다 | 채점 결과와 다른 형식의 문제가 섞이지 않게 |
| G-06 | 녹음 파일은 임시 파일을 만들지 않고 메모리의 바이트를 그대로 전사 API에 보낸다 | 디스크에 쓰지 않는 쪽이 더 단순하고 BR-06에도 맞다 |
| G-07 | 학번 문맥 "ID"는 앞에 영문자가 붙지 않을 때만 본다(`valid 12345678`은 가리지 않음) | 영어 단어 속 "id"를 학번으로 오인하지 않게 |
| G-08 | 근거 쪽(호출 3·4·5)은 메타 페이지가 아닌 본문 쪽을 먼저, 최대 8쪽 | 4.2 "본문·예제가 있는 쪽부터"를 가장 단순하게 |
| G-09 | 요약 노트의 교수님 말은 유형과 상관없이 강도 높은 순으로 3개(같은 문장은 한 번) | F13 "강한 것부터 3개" |
| G-10 | E-14(새로고침하면 사라짐)는 S01 아래에 항상 안내 문구로 보인다 | 새 세션에서 새로고침 여부를 알 방법이 없다 |
| G-11 | 하루 AI 호출 상한에 닿으면 새 분석도 E-17로 막는다 | 분석도 AI 작업이다 |
| G-12 | 받아쓰기(STT)도 AI 호출로 보고, 그 뒤에 실패한 분석은 횟수를 돌려주지 않는다 | F14 "AI를 한 번이라도 부른 뒤 실패하면 돌려주지 않는다" |
| G-13 | 학우 질문 기록(F12)은 만들지 않았다 | 개발기획안의 "시간 남으면" 항목, 당일 규칙상 개선은 하지 않음 |
| G-14 | 내려받기 버튼은 눌러도 화면을 다시 그리지 않는다(`on_click="ignore"`) | 내려받을 때마다 다시 그리면 긴 화면이 깜빡인다 |
| G-15 | 사이드바 ③은 진단 대상이 정해진 뒤, ④는 채점이 끝난 뒤(또는 "채점 못한 문제는 빼고 공부 순서 보기"를 누른 뒤) 열린다 | 3.7 "앞 단계가 끝나야 다음 단계가 열린다" |
