### 2. 트리의 높이와 깊이  `자세히`
 `앎`  `출제 점수 58`  `복습만` 깊이(depth)는 '루트에서 그 노드까지의 경로 길이(간선 수)'이다(p.5). 높이(height)는 '그 노드에서 가장 먼 단말 노드까지의 경로 길이'이다(p.5).  
루트의 깊이는 0이고 E의 깊이는 2이다(p.5). 단말 노드의 높이는 0이고 B의 높이는 2이며, 트리의 높이는 루트의 높이와 같은 3이다(p.5). 같은 노드라도 깊이와 높이는 다를 수 있으며, 노드 E는 깊이 2, 높이 0이다(p.5).  
두 값은 세는 방향이 다르다. 깊이는 위에서 세고, 높이는 아래에서 센다(p.5). 교수님은 '깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.'라고 강조했다(p.5). 요약 페이지에도 '깊이(위에서)와 높이(아래에서)'로 정리되어 있다(p.20). 연습문제 2번은 노드 D의 깊이와 높이, 트리 전체의 높이를 구하라고 한다(p.19).  
**핵심**

- 깊이(depth) = 루트에서 그 노드까지의 경로 길이(간선 수), 위에서 센다 (루트의 깊이 = 0)  
- 높이(height) = 그 노드에서 가장 먼 단말 노드까지의 경로 길이, 아래에서 센다 (단말 노드의 높이 = 0)  
- 트리의 높이 = 루트의 높이 (p.5 그림의 트리에서는 3)  
- 같은 노드라도 깊이와 높이는 다를 수 있다 (p.5 그림: 노드 E는 깊이 2, 높이 0)  
**자주 하는 실수**

- 깊이와 높이를 혼동한다. 교수님은 '이건 매년 헷갈리는 학생이 많아요.'라고 경고했으며, 깊이는 루트에서 위로부터, 높이는 가장 먼 단말 노드까지 아래로 센다  
- 같은 노드의 깊이와 높이가 같다고 생각한다. 노드 E는 깊이 2, 높이 0으로 서로 다르다  
**교수님 말**

- “이건 매년 헷갈리는 학생이 많아요.”  
- “깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.”  
근거 페이지 (p.5) (p.19) (p.20)

### 4. 완전 이진 트리의 배열 표현  `보통`
 `헷갈림`  `출제 점수 28`  `복습만` 완전 이진 트리는 배열에 빈칸 없이 저장할 수 있으며, 루트를 인덱스 1에 둔다(p.7). 노드 i의 왼쪽 자식은 2i, 오른쪽 자식은 2i+1, 부모는 i // 2이고 인덱스 0은 비워 둔다(p.7). 힙도 완전 이진 트리이므로 이 배열 표현을 쓰며, 부모 i의 자식은 2i, 2i+1이다(p.14). 교수님은 '이 공식, 조금 있다가 힙 코드에서 그대로 나오니까 외워두시면 편합니다.'라고 강조했는데, 진단에서 확신 없이 찍어서 맞혔으므로 이 공식을 확실히 외워 두어야 한다(p.7).  
**핵심**

- 루트는 인덱스 1, 인덱스 0은 비워 둔다(p.7)  
- 노드 i: 왼쪽 자식 = 2i, 오른쪽 자식 = 2i+1, 부모 = i // 2(p.7)  
- 힙(최대 힙·최소 힙)도 같은 배열 표현을 그대로 사용한다(p.14)  
**자주 하는 실수**

- 루트를 인덱스 1에 두고 인덱스 0은 비워 둔다는 점을 놓친다(p.7)  
**교수님 말**

- “이 공식, 조금 있다가 힙 코드에서 그대로 나오니까 외워두시면 편합니다.”  
근거 페이지 (p.7) (p.14)

### 5. 이진 트리의 순회 (전위·중위·후위)  `자세히`
 `헷갈림`  `출제 점수 87`  `다음` 순회(traversal)는 트리의 모든 노드를 한 번씩 방문하는 것이다(p.8). 루트(V)를 언제 방문하느냐에 따라 전위 순회(preorder)는 V → L → R, 중위 순회(inorder)는 L → V → R, 후위 순회(postorder)는 L → R → V의 세 가지가 있다(p.8).  
수식 트리 예제에서 전위 순회는 + * a b - c d, 중위 순회는 a * b + c - d, 후위 순회는 a b * c d - +이다(p.9). 수식 트리를 후위 순회하면 후위 표기식이 되고, 이진 탐색 트리를 중위 순회하면 오름차순으로 값이 나온다(p.8, p.9). 중위 순회에서는 L → V → R 규칙에 따라 루트가 왼쪽 서브트리를 모두 방문한 뒤 오른쪽보다 먼저 방문되어 그 위치에 오므로, 결과만 쓰지 말고 이 규칙과 설명을 함께 적어야 한다(p.8).  
세 방법 모두 재귀로 간단히 구현되며, 코드에서는 print(n.data)의 위치만 V L R, L V R, L R V 순서에 맞게 달라진다(p.8, p.10). 노드 n개를 각각 한 번씩 방문하므로 시간 복잡도는 O(n)이다(p.10). 교수님은 '트리 그림 하나 주고 세 가지 순회 결과 쓰라고 하면 딱 한 문제가 됩니다'라고 강조했고, 연습문제 1번에도 같은 유형이 있다(p.19).  
**핵심**

- 전위 순회 V → L → R, 중위 순회 L → V → R, 후위 순회 L → R → V  
- 중위 순회 답에는 결과와 함께 L → V → R 규칙, 루트가 왼쪽 서브트리를 모두 방문한 뒤 오른쪽보다 먼저 방문된다는 설명을 쓴다  
- 세 순회 모두 재귀로 구현하며 시간 복잡도는 O(n)이다  
- 수식 트리를 후위 순회하면 후위 표기식, 이진 탐색 트리를 중위 순회하면 오름차순이다  
- 트리 그림 하나로 세 가지 순회 결과를 쓰는 문제가 출제될 수 있다(연습문제 1번)  
**자주 하는 실수**

- 중위 순회 결과만 쓰고 L → V → R 규칙과 루트가 그 위치에 오는 이유를 답안에 빠뜨려 감점된다(절차 누락)  
**교수님 말**

- “이 중에서 순회하고 힙 삽입·삭제는 중간고사 범위의 핵심이라고 미리 말씀드립니다.”  
- “중위 순회 결과를 쓰는 문제, 이건 시험에 내기 좋죠.”  
- “트리 그림 하나 주고 세 가지 순회 결과 쓰라고 하면 딱 한 문제가 됩니다.”  
근거 페이지 (p.8) (p.9) (p.10) (p.19)

### 6. 이진 탐색 트리의 정의와 성질  `보통`
 `헷갈림`  `출제 점수 24`  `복습만` 이진 탐색 트리(BST)는 탐색을 위해 정렬 규칙을 가진 이진 트리이다(p.11). 모든 노드에 대해 '왼쪽 서브트리 < 노드 < 오른쪽 서브트리'이며, 중복된 키는 없다고 가정한다(p.11). 이진 탐색 트리를 중위 순회(L → V → R)하면 오름차순으로 값이 나오며, p.11 그림의 중위 순회 결과는 7 18 26 35 50 68 99이다(p.8, p.11). 이진 탐색 트리의 탐색·삽입은 O(h)이다(p.20).  
**핵심**

- 모든 노드에 대해 왼쪽 서브트리 < 노드 < 오른쪽 서브트리 (중복된 키는 없다고 가정)  
- 중위 순회(L → V → R) 결과 = 오름차순  
- 탐색·삽입 시간 복잡도 O(h)  
근거 페이지 (p.8) (p.11) (p.20)

### 7. 이진 탐색 트리의 탐색과 삽입  `자세히`
 `헷갈림`  `출제 점수 57`  `다음` 이진 탐색 트리는 '왼쪽 < 루트 < 오른쪽' 조건을 만족하는 이진 트리이다(p.20). 탐색은 루트부터 시작해 키가 작으면 왼쪽, 크면 오른쪽으로 내려가며, 같은 키를 만나면 그 노드를 반환하고 None에 닿으면 None을 반환한다(p.12).  
삽입은 탐색이 실패한 위치(None)에 새 노드를 붙이는 것이므로 항상 단말 노드로 삽입된다(p.12). insert_bst 코드는 r이 None이면 새 노드 n을 반환하고, n.data < r.data이면 r.left에, n.data > r.data이면 r.right에 재귀로 삽입한 뒤 r을 반환한다(p.12). 따라서 새 노드의 자리는 루트부터 크기를 비교하며 내려가는 과정을 끝까지 따라가야 정해진다(p.12). 교수님은 '삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요'라고 강조했으며, 연습문제 3도 50, 30, 70, 20, 40, 60을 순서대로 삽입한 결과를 그리는 문제이다(p.19).  
탐색과 삽입의 시간 복잡도는 트리의 높이 h에 비례하여 O(h)이다(p.12). 균형이 잡히면 O(log n), 편향되면 O(n)이다(p.12).  
**핵심**

- 탐색: 루트부터 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다 (p.12)  
- 삽입: 탐색이 실패한 위치(None)에 새 노드를 붙인다 → 항상 단말 노드 (p.12)  
- 삽입 순서를 주고 트리를 그리는 문제가 자주 나오므로, 노드마다 루트부터 크기를 비교하며 내려간 경로를 적는 연습이 필요하다 (p.19)  
- 탐색·삽입 시간 복잡도 O(h): 균형이면 O(log n), 편향되면 O(n) (p.12, p.20)  
**자주 하는 실수**

- 삽입 위치만 쓰고, 루트부터 크기를 비교하며 내려가는 과정을 빠뜨린다 (p.12)  
- 삽입이 탐색에 실패한 빈 자리(None)에 붙어 단말 노드가 된다는 이유를 쓰지 않는다 (p.12)  
**교수님 말**

- “삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.”  
근거 페이지 (p.12) (p.19) (p.20)

### 9. 힙의 정의 (최대 힙·최소 힙)  `자세히`
 `모름`  `출제 점수 27`  `다음` 힙(heap)은 '완전 이진 트리이면서, 모든 노드가 힙 조건을 만족하는 트리'이다(p.14). 최대 힙은 부모 ≥ 자식이어서 루트가 최댓값이고, 최소 힙은 부모 ≤ 자식이어서 루트가 최솟값이다(p.14). 형제 사이의 순서는 없으며, 힙은 정렬된 것이 아니다(p.14). 교수님은 '주의할 건 형제끼리는 순서가 없다는 거예요.'라고 경고했다(p.14). 교수님이 '오늘의 핵심이에요.'라고 강조했고 진단에서 0/10이었으므로, 완전 이진 트리와 힙 조건을 둘 다 만족해야 힙이라는 정의부터 정확히 외운다(p.14).  
힙은 완전 이진 트리이므로 배열로 표현하며, 부모 i의 자식은 2i, 2i+1이다(p.14). 최대 힙 그림(p.14 그림)의 배열은 [0]이 '-'이고 [1]부터 93, 80, 75, 50, 62, 70, 33이다(p.14).  
힙에 대한 연산은 삽입이 '마지막에 넣고 업힙', 삭제가 '루트 꺼내고 마지막을 올려 다운힙'이며, 둘 다 O(log n)이다(p.20).  
**핵심**

- 힙 = 완전 이진 트리 + 힙 조건 (둘 다 만족해야 한다)  
- 최대 힙: 부모 ≥ 자식 → 루트가 최댓값 / 최소 힙: 부모 ≤ 자식 → 루트가 최솟값  
- 형제 사이의 순서는 없다 (정렬된 것이 아님)  
- 배열 표현: 부모 i → 자식 2i, 2i+1  
- 삽입(업힙)·삭제(다운힙) 모두 O(log n)  
**자주 하는 실수**

- 형제끼리도 크기 순서가 있다고 생각하거나, 힙을 정렬된 구조로 착각한다 (교수님의 실수 경고)  
- 최대 힙(부모 ≥ 자식, 루트 최댓값)과 최소 힙(부모 ≤ 자식, 루트 최솟값)의 부등호 방향을 뒤바꿔 기억한다 (진단 0/10 오답)  
**교수님 말**

- “오늘의 핵심이에요.”  
- “주의할 건 형제끼리는 순서가 없다는 거예요.”  
근거 페이지 (p.14) (p.20)

### 10. 힙의 삽입 연산  `자세히`
 `앎`  `출제 점수 100`  `복습만` 힙은 완전 이진 트리에 힙 조건을 더한 구조이며 배열로 표현한다(p.20). 힙의 삽입 연산은 새 항목을 마지막 위치(배열의 끝)에 넣어 완전 이진 트리를 유지하는 것에서 시작한다(p.15).  
그 다음 부모와 비교해 더 크면 부모와 교환하며 위로 올라가고(업힙, sift-up), 이렇게 해서 힙 조건을 회복한다(p.15). p.15 그림의 예에서는 85를 마지막에 추가한 뒤 50, 80과 교환하며 올라가다가 93보다 작으므로 정지한다(p.15). 코드의 insert는 heap.append(n)으로 끝에 넣은 뒤, i != 1 이고 n > self.heap[i // 2]인 동안 부모 값을 내리고 i = i // 2로 올라간다(p.17).  
시간 복잡도는 트리 높이만큼만 올라가므로 O(log n)이다(p.15). 교수님은 '다시 한 번, 힙 삽입은 마지막에 넣고 업힙, 시간은 로그 n.'이라고 강조했다(p.20). 또 교수님은 '과정을 그림으로 그리라는 문제가 나올 수 있어요.'라고 말했으며, 연습문제 4번이 최대 힙 [ -, 90, 70, 80, 30, 50, 60 ]에 95를 삽입하는 과정을 단계별로 그리고 교환 횟수를 쓰는 문제다(p.19).  
**핵심**

- 삽입 = 마지막(배열의 끝)에 넣고 업힙 (p.15, p.20)  
- 업힙 = 부모와 비교해 더 크면 교환하며 위로 올라가고, 부모보다 크지 않으면 멈춘다 (p.15)  
- 시간 복잡도 O(log n): 트리 높이만큼만 올라간다 (p.15)

### 11. 힙의 삭제 연산  `자세히`
 `모름`  `출제 점수 86`  `지금 당장` 힙에서 삭제는 항상 루트(최댓값)를 꺼내는 것이다(p.16). 교수님은 '삭제 과정도 시험에 나옵니다.'라고 강조했으며, 힙의 삭제 연산은 p.16에 정리되어 있다(p.16).  
절차는 두 단계다. ① 루트를 꺼내고, 마지막 노드를 루트 자리로 옮긴다(p.16). ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려간다(다운힙, sift-down)(p.16). 예로 93 삭제 후 33을 루트로 올리고 80, 62와 교환하며 내려가면 결과는 [80, 62, 75, 50, 33, 70]이다(p.16). 코드에서는 root = self.heap[1]을 저장하고 last = self.heap.pop()으로 마지막 값을 꺼낸 뒤, 더 큰 자식을 선택해 last >= self.heap[child]이면 멈춘다(p.17).  
힙 삭제의 시간 복잡도는 O(log n)이다(p.16). 요약에서도 힙 삽입은 마지막에 넣고 업힙, 힙 삭제는 루트 꺼내고 마지막을 올려 다운힙이며 둘 다 O(log n)이라고 정리한다(p.20).  
**핵심**

- 절차: ① 루트를 꺼내고 마지막 노드를 루트 자리로 옮긴다 → ② 더 큰 자식과 비교해 작으면 교환하며 내려간다 (다운힙, sift-down) (p.16)  
- 시간 복잡도 O(log n), 삽입(업힙)과 삭제(다운힙) 모두 O(log n) (p.16, p.20)  
- 진단에서 '모름'으로 표시한 개념이므로 ①→② 순서와 '더 큰 자식과 비교'를 처음부터 외운다

### 12. 우선순위 큐와 힙  `자세히`
 `모름`  `출제 점수 51`  `지금 당장` 우선순위 큐는 들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐이다(p.18). 연산은 insert(item)과 remove()이며, remove()는 가장 높은 우선순위를 반환한다(p.18). 응용으로는 운영체제 작업 스케줄링, 다익스트라 최단 경로, 허프만 코딩이 있다(p.18).  
힙은 완전 이진 트리에 힙 조건을 더한 것이며 배열로 표현한다(p.20). 힙 삽입은 마지막에 넣고 업힙하는 것이고, 힙 삭제는 루트를 꺼내고 마지막을 올려 다운힙하는 것이다(p.20). 삽입과 삭제 모두 O(log n)이다(p.20).  
구현별로 비교하면 정렬 안 된 배열은 삽입 O(1), 삭제 O(n)이고 정렬된 배열은 삽입 O(n), 삭제 O(1)이며 힙은 삽입과 삭제 모두 O(log n)이다(p.18). 따라서 힙으로 구현하면 두 연산 모두 O(log n)이 되고, 배열·연결 리스트는 둘 중 하나가 O(n)이다(p.18). 이것이 우선순위 큐를 힙으로 구현하는 이유이며, 진단에서 모름으로 표시한 부분이므로 이 비교표를 반드시 외워야 한다(p.18).  
**핵심**

- 우선순위 큐: 우선순위가 높은 항목부터 나가는 큐, 연산은 insert(item)과 remove()  
- 힙으로 구현하는 이유: 삽입·삭제 모두 O(log n) (배열·연결 리스트는 둘 중 하나가 O(n))  
- 정렬 안 된 배열: 삽입 O(1)·삭제 O(n) / 정렬된 배열: 삽입 O(n)·삭제 O(1) / 힙: 둘 다 O(log n)  
- 힙 삽입 = 마지막에 넣고 업힙, 힙 삭제 = 루트 꺼내고 마지막을 올려 다운힙  
- 힙 정렬: 전체 O(n log n), 추가 메모리 거의 없음  
**자주 하는 실수**

- 우선순위 큐를 힙으로 구현하는 이유를 '두 연산 모두 O(log n)'이라는 시간 복잡도로 설명하지 못하고 넘어간다(진단 0/10, 무응답)  
- 정렬 안 된 배열과 정렬된 배열은 삽입과 삭제 중 한쪽이 O(n)이라는 점을 놓친다
