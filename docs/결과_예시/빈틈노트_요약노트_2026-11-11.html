2. 트리의 깊이와 높이 자세히

앎출제 점수 58복습만

깊이(depth)는 루트에서 그 노드까지의 경로 길이(간선 수)이며, 루트의 깊이는 0이고 E의 깊이는 2이다 p.5. 높이(height)는 그 노드에서 가장 먼 단말 노드까지의 경로 길이이다 p.5.

구분 기준은 '깊이는 위에서 세고, 높이는 아래에서 센다'이다 p.5. 요약 페이지에서도 트리 용어를 깊이(위에서)와 높이(아래에서)로 정리한다 p.20. 단말 노드의 높이는 0이고 B의 높이는 2이다 p.5. 트리의 높이는 루트의 높이와 같으며 이 자료에서는 3이다 p.5.

같은 노드라도 깊이와 높이는 다를 수 있으며, 노드 E는 깊이 2, 높이 0이다 p.5. 교수님은 '깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.'라고 강조했다 녹음.

핵심

  • 깊이 = 루트에서 그 노드까지의 간선 수, 루트의 깊이 = 0
  • 높이 = 그 노드에서 가장 먼 단말 노드까지의 간선 수, 단말 노드의 높이 = 0
  • 깊이는 위(루트)에서 세고, 높이는 아래(단말)에서 센다
  • 트리의 높이 = 루트의 높이 (p.5 그림의 트리는 3)

자주 하는 실수

  • 깊이와 높이를 서로 바꿔 센다. 교수님은 '이건 매년 헷갈리는 학생이 많아요.'라고 경고했다 녹음.
  • 한 노드의 깊이와 높이가 같다고 생각한다. 노드 E는 깊이 2, 높이 0으로 서로 다르다 p.5.

교수님 말

  • “이건 매년 헷갈리는 학생이 많아요.” 녹음
  • “깊이는 위에서 세고 높이는 아래에서 센다, 이것만 기억하세요.” 녹음

근거 페이지 p.5p.20

4. 완전 이진 트리의 배열 표현 보통

헷갈림출제 점수 28복습만

완전 이진 트리는 루트를 인덱스 1에 두면 배열에 빈칸 없이 저장할 수 있다 p.7. 노드 i의 왼쪽 자식은 2i, 오른쪽 자식은 2i+1, 부모는 i // 2이고 인덱스 0은 비워 둔다 p.7. 힙도 완전 이진 트리이므로 같은 방식으로 배열에 표현하며, 배열 [93, 80, 75, 50, 62, 70, 33]에서 인덱스 1의 93의 자식은 인덱스 2, 3의 80, 75이다 p.14. 교수님은 '이 공식, 조금 있다가 힙 코드에서 그대로 나오니까 외워두시면 편합니다.'라고 강조했다 녹음.

핵심

  • 루트는 인덱스 1, 인덱스 0은 비워 둔다
  • 노드 i: 왼쪽 자식 = 2i, 오른쪽 자식 = 2i+1, 부모 = i // 2 (진단에서 헷갈린 부분이므로 세 식을 구분해 외운다)
  • 힙도 이 배열 표현을 그대로 사용한다 (부모 i → 자식 2i, 2i+1)

자주 하는 실수

  • 루트를 인덱스 1에 두고 인덱스 0은 비워 둔다는 전제를 빠뜨린다

교수님 말

  • “이 공식, 조금 있다가 힙 코드에서 그대로 나오니까 외워두시면 편합니다.” 녹음

5. 이진 트리의 순회(전위·중위·후위) 자세히

헷갈림출제 점수 90다음

순회(traversal)는 트리의 모든 노드를 한 번씩 방문하는 것이다 p.8. 루트(V)를 언제 방문하느냐에 따라 전위 순회(preorder) V → L → R, 중위 순회(inorder) L → V → R, 후위 순회(postorder) L → R → V의 세 가지로 나뉜다 p.8.

세 방법 모두 재귀로 간단히 구현되며, 코드에서는 n이 None이 아닐 때 print(n.data)의 위치만 전위는 맨 앞, 중위는 가운데, 후위는 맨 뒤로 달라진다 p.10. 수식 트리 예제의 방문 순서는 전위 + * a b - c d, 중위 a * b + c - d, 후위 a b * c d - +이다 p.9. 수식 트리를 후위 순회하면 후위 표기식이 된다 p.9. 진단에서 중위 순회 결과는 맞혔지만 L → V → R 규칙을 말로 설명하지 못했으므로, 중위 순회는 왼쪽을 먼저 방문하고 그다음 루트(V)를 방문한 뒤 오른쪽을 방문한다는 점을 설명할 수 있어야 한다 p.8.

노드 n개를 각각 한 번씩 방문하므로 시간 복잡도는 O(n)이다 p.10. 교수님은 '중위 순회 결과를 쓰는 문제, 이건 시험에 내기 좋죠.'라고 강조했다 녹음.

핵심

  • 전위 VLR, 중위 LVR, 후위 LRV: 루트(V)를 방문하는 시점만 다르다
  • 재귀로 구현하며 노드를 한 번씩 방문하므로 시간 복잡도는 O(n)이다
  • 중위 순회는 L → V → R 규칙을 말로 설명할 수 있어야 한다(진단에서 헷갈린 부분)
  • 수식 트리를 후위 순회하면 후위 표기식이 된다
  • 이진 탐색 트리를 중위 순회하면 오름차순으로 값이 나온다

자주 하는 실수

  • 중위 순회 결과는 맞혀도 L → V → R 방문 규칙을 말로 설명하지 못하는 실수를 한다(진단 결과)
  • 루트(V)의 방문 위치를 전위·중위·후위에서 서로 바꿔 혼동한다

교수님 말

  • “중위 순회 결과를 쓰는 문제, 이건 시험에 내기 좋죠.” 녹음
  • “이 중에서 순회하고 힙 삽입·삭제는 중간고사 범위의 핵심이라고 미리 말씀드립니다.” 녹음
  • “트리 그림 하나 주고 세 가지 순회 결과 쓰라고 하면 딱 한 문제가 됩니다.” 녹음

근거 페이지 p.8p.9p.10

7. 이진 탐색 트리의 탐색과 삽입 자세히

헷갈림출제 점수 57다음

탐색은 '루트부터 시작, 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다' p.12. 이진 탐색 트리는 '왼쪽 < 루트 < 오른쪽'을 만족한다 p.20.

삽입은 '탐색이 실패한 위치(None)에 새 노드를 붙인다'이며, 그래서 '항상 단말 노드로 삽입'된다 p.12. insert_bst 코드는 루트 r이 None이면 새 노드 n을 반환하고, n.data < r.data이면 왼쪽, n.data > r.data이면 오른쪽으로 재귀 호출한 뒤 r을 반환한다 p.12. 예제는 빈 트리에 35, 18, 68, 7, 26 순서로 삽입하는 것이다 p.12. 진단에서는 35→18→26으로 내려가며 키를 비교하는 과정과, 탐색이 실패한 빈 자리(None)에 붙어 단말 노드가 된다는 설명이 빠졌으므로 이 두 가지를 함께 말할 수 있어야 한다 p.12. 교수님은 '삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.'라고 강조했다 녹음.

시간 복잡도는 '트리의 높이 h에 비례'하므로 O(h)이다 p.12. 균형이 잡히면 O(log n), 편향되면 O(n)이다 p.12.

핵심

  • 탐색: 루트부터 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다
  • 삽입: 탐색이 실패한 위치(None)에 새 노드를 붙인다 → 항상 단말 노드
  • 삽입 순서가 주어지면 노드마다 루트부터 키를 비교하며 내려가 위치를 정한다 (예: 35, 18, 68, 7, 26)
  • 시간 복잡도 O(h): 균형이 잡히면 O(log n), 편향되면 O(n)
  • 이진 탐색 트리 조건: 왼쪽 < 루트 < 오른쪽

자주 하는 실수

  • 삽입 위치만 쓰고 키를 비교하며 내려가는 과정과 None 자리에 붙어 단말 노드가 된다는 설명을 빼먹는다
  • 시간 복잡도를 O(log n)으로만 외우고, 편향되면 O(n)이 된다는 점(O(h))을 놓친다

교수님 말

  • “삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.” 녹음

근거 페이지 p.12p.20

9. 힙의 정의와 최대 힙·최소 힙 자세히

모름출제 점수 27다음

힙(heap)은 완전 이진 트리이면서, 모든 노드가 힙 조건을 만족하는 트리다 p.14. 최대 힙은 부모 ≥ 자식이며 루트가 최댓값이다 p.14. 최소 힙은 부모 ≤ 자식이며 루트가 최솟값이다 p.14.

형제 사이의 순서는 없으며 정렬된 것이 아니다 p.14. 교수님은 '주의할 건 형제끼리는 순서가 없다는 거예요.'라고 경고했다 녹음. 최대 힙 예시의 배열은 [0]이 '-'이고 [1]~[7]이 [93, 80, 75, 50, 62, 70, 33]이다(p.14 그림).

힙은 완전 이진 트리이므로 배열로 표현하며, 부모 i의 자식은 2i, 2i+1이다 p.14. 힙 삽입(마지막에 넣고 업힙)과 힙 삭제(루트를 꺼내고 마지막을 올려 다운힙)는 둘 다 O(log n)이다 p.20.

핵심

  • 힙 = 완전 이진 트리 + 힙 조건 p.14
  • 최대 힙: 부모 ≥ 자식, 루트가 최댓값 / 최소 힙: 부모 ≤ 자식, 루트가 최솟값 p.14
  • 형제 사이의 순서는 없다. 정렬된 것이 아니다 p.14
  • 배열 표현: 부모 i → 자식 2i, 2i+1 p.14
  • 교수님이 '오늘의 핵심이에요.'라고 강조한 내용이다 녹음

자주 하는 실수

  • 형제끼리도 순서가 있다고 생각한다. 교수님이 경고했듯 형제 사이에는 순서가 없고, 힙은 정렬된 것이 아니다(p.14, 녹음).
  • 진단에서 ④를 골랐지만 정답은 ③이었으므로, 최대 힙(부모 ≥ 자식)과 최소 힙(부모 ≤ 자식)의 조건과 루트 값을 다시 확인한다 p.14.

교수님 말

  • “오늘의 핵심이에요.” 녹음
  • “주의할 건 형제끼리는 순서가 없다는 거예요.” 녹음

근거 페이지 p.14p.20

10. 힙의 삽입 연산(업힙) 자세히

앎출제 점수 100복습만

힙은 완전 이진 트리에 힙 조건을 더한 구조이고 배열로 표현한다 p.20. 힙의 삽입은 새 항목을 마지막 위치(배열의 끝)에 넣은 뒤 업힙(sift-up)으로 힙 조건을 회복하는 연산이다 p.15.

먼저 새 항목을 마지막 위치(배열의 끝)에 넣으며, 이렇게 하면 완전 이진 트리가 유지된다 p.15. 그다음 부모와 비교해 더 크면 부모와 교환하며 위로 올라가고, 이 과정이 업힙이며 힙 조건을 회복한다 p.15. p.15 그림에서는 85를 마지막에 추가한 뒤 50, 80과 교환하며 올라가고, 93보다 작으므로 정지한다(p.15 그림).

시간 복잡도는 트리 높이만큼만 올라가므로 O(log n)이다 p.15. 힙 삭제도 O(log n)이며, 삽입은 마지막에 넣고 업힙, 삭제는 루트를 꺼내고 마지막을 올려 다운힙을 한다는 점이 다르다 p.20. 교수님은 '다시 한 번, 힙 삽입은 마지막에 넣고 업힙, 시간은 로그 n.'이라고 강조했다 녹음.

핵심

  • 힙 삽입 = 마지막 위치(배열의 끝)에 넣고 업힙(sift-up)으로 올라간다 p.15p.20.
  • 업힙 절차: 부모와 비교해 더 크면 부모와 교환하며 위로 올라간다 p.15.
  • 멈추는 조건: 부모보다 크지 않으면 올라가지 않고 정지한다. 그림에서는 85가 93보다 작으므로 정지한다 p.15.
  • 시간 복잡도는 트리 높이만큼만 올라가므로 O(log n)이다 p.15.
  • 코드에서는 insert가 heap.append(n) 후 while i != 1 and n > self.heap[i // 2] 동안 i = i // 2로 올라간다 p.17.

자주 하는 실수

  • 삽입(마지막에 넣고 업힙)과 삭제(루트를 꺼내고 마지막을 올려 다운힙)의 과정을 혼동한다 p.20.
  • 부모와 비교해 더 크면 교환하며 올라가는 과정을 끝까지 반복하지 않고 한 번만 비교하거나, 정지 조건(그림에서는 93보다 작으므로 정지)을 놓친다 p.15.

교수님 말

  • “이건 꼭 알아두세요.” 녹음
  • “다시 한 번, 힙 삽입은 마지막에 넣고 업힙, 시간은 로그 n.” 녹음
  • “4번 5번은 꼭 풀어보세요.” 녹음

근거 페이지 p.15p.17p.20

11. 힙의 삭제 연산(다운힙) 자세히

모름출제 점수 86지금 당장

힙에서 삭제는 항상 루트(최댓값)를 꺼내는 것이다 p.16. 교수님은 '삽입이랑 세트로 기억하세요.'라고 강조했다 녹음.

① 루트를 꺼내고, 마지막 노드를 루트 자리로 옮긴다 p.16. ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려가는데, 이것이 다운힙(sift-down)이다 p.16. 예를 들어 93을 삭제하고 33을 루트로 옮긴 뒤 80, 62와 교환하며 내려가면 결과는 [80, 62, 75, 50, 33, 70]이다 p.16.

시간 복잡도는 O(log n)이며, 삽입(마지막에 넣고 업힙)과 삭제(루트를 꺼내고 마지막을 올려 다운힙) 둘 다 O(log n)이다 p.16p.20. 교수님은 '더 큰 자식과 비교한다, 이 부분에서 실수가 많아요.'라고 경고했다 녹음.

핵심

  • 삭제 절차는 ① 루트를 꺼내고 마지막 노드를 루트 자리로 옮긴다 → ② 더 큰 자식과 비교해 작으면 교환하며 내려간다(다운힙)이다 p.16
  • 시간 복잡도는 O(log n)이며 삽입(업힙)과 세트로 외운다 p.16p.20
  • 코드에서는 child < size이고 heap[child] < heap[child + 1]이면 child += 1로 더 큰 자식을 고르고, last >= heap[child]이면 break한다 p.17
  • 진단에서 '모름'으로 표시한 개념이므로 p.16 그림의 결과 [80, 62, 75, 50, 33, 70]을 직접 따라 그려 보며 학습 목표인 '그림으로 설명'을 연습한다 p.3p.16
  • 교수님은 '삭제 과정도 시험에 나옵니다.'라고 했고 '4번 5번은 꼭 풀어보세요.'라고 말했다 녹음

자주 하는 실수

  • 두 자식 중 더 큰 자식과 비교해야 하는데 이 부분에서 실수가 많다고 교수님이 경고했다
  • 진단에서 '모르겠어요'를 골라 모름으로 표시했으므로, 마지막 노드를 루트로 옮기는 ①단계와 더 큰 자식과 교환하며 내려가는 ②단계의 순서를 건너뛰지 않도록 주의한다 p.16

12. 우선순위 큐와 힙 구현 자세히

모름출제 점수 51지금 당장

우선순위 큐는 '들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐'다 p.18. 연산은 insert(item)와 remove()이며, remove()는 가장 높은 우선순위 항목을 반환한다 p.18. 응용으로는 운영체제 작업 스케줄링, 다익스트라 최단 경로, 허프만 코딩이 있다 p.18.

우선순위 큐는 힙으로 구현하며, 힙은 완전 이진 트리 + 힙 조건이고 배열로 표현한다 p.20. 힙 삽입은 마지막에 넣고 업힙하고, 힙 삭제는 루트를 꺼내고 마지막을 올려 다운힙한다 p.20.

힙으로 구현하면 insert와 remove 두 연산 모두 O(log n)이다 p.18. 정렬 안 된 배열은 삽입 O(1), 삭제(최댓값) O(n)이고, 정렬된 배열은 삽입 O(n), 삭제 O(1)이어서 배열·연결 리스트는 둘 중 하나가 O(n)이다 p.18. 학습 목표가 '힙으로 우선순위 큐를 구현하는 이유를 설명할 수 있다'이므로 p.3, 진단에서 '모름'으로 표시한 이 부분은 '두 연산 모두 O(log n)이라 배열·연결 리스트보다 유리하다'로 정리한다 p.18.

핵심

  • 진단에서 '모름'으로 표시한 부분: 힙으로 구현하는 이유 = 삽입·삭제 모두 O(log n) (배열·연결 리스트는 둘 중 하나가 O(n))
  • 우선순위 큐: 우선순위가 높은 항목부터 나가는 큐, 연산은 insert(item), remove()
  • 힙 삽입 = 마지막에 넣고 업힙, 힙 삭제 = 루트 꺼내고 마지막을 올려 다운힙, 둘 다 O(log n)
  • 정렬 안 된 배열 삽입 O(1)·삭제 O(n), 정렬된 배열 삽입 O(n)·삭제 O(1), 힙 삽입 O(log n)·삭제 O(log n)
  • 힙 정렬은 전체 O(n log n)이고 추가 메모리가 거의 없다

자주 하는 실수

  • 힙으로 구현하는 이유를 몰라 답하지 못한다. 핵심은 두 연산 모두 O(log n)이라는 점이며, 배열·연결 리스트는 둘 중 하나가 O(n)이다
  • 정렬 안 된 배열(삽입 O(1), 삭제 O(n))과 정렬된 배열(삽입 O(n), 삭제 O(1))의 복잡도를 서로 바꿔 외운다
