**5. 이진 트리의 순회**  `자세히` `출제 점수 90` `헷갈림`

순회(traversal)는 트리의 모든 노드를 한 번씩 방문하는 것이다 (p.8). 루트(V)를 언제 방문하느냐에 따라 전위 순회(preorder) V → L → R, 중위 순회(inorder) L → V → R, 후위 순회(postorder) L → R → V의 세 가지로 나뉜다 (p.8).

세 방법 모두 재귀로 간단히 구현되며, 코드에서는 n이 None이 아닐 때 print(n.data, end=' ')의 위치만 전위(왼쪽·오른쪽 호출 앞), 중위(두 호출 사이), 후위(두 호출 뒤)로 달라진다 (p.10). 수식 트리 예제의 방문 순서는 전위 + * a b - c d, 중위 a * b + c - d, 후위 a b * c d - +이다 (p.9). 진단에서 빠뜨린 부분은 후위 순회가 L → R → V이므로 루트가 가장 마지막에 방문된다는 점과 그 이유이며, 답안에 이 절차를 함께 적어야 한다 (p.8).

노드 n개를 각각 한 번씩 방문하므로 시간 복잡도는 O(n)이다 (p.10). 이진 탐색 트리를 중위 순회하면 오름차순으로 값이 나온다 (p.8). 교수님은 '중위 순회 결과를 쓰는 문제, 이건 시험에 내기 좋죠.'라고 강조했다 (p.8).

**핵심**

- 전위 순회 V → L → R, 중위 순회 L → V → R, 후위 순회 L → R → V  (p.8)
- 후위 순회(L → R → V)는 루트가 가장 마지막에 방문된다  (p.8)
- 세 순회 모두 재귀로 구현하며 노드를 한 번씩 방문하므로 O(n)  (p.10)
- 수식 트리를 후위 순회하면 후위 표기식이 된다  (p.9)
- 이진 탐색 트리를 중위 순회하면 오름차순이 된다  (p.8)

**자주 하는 실수**

- 후위 순회에서 루트가 마지막에 방문된다는 점과 그 이유(L → R → V)를 빠뜨리고 결과만 적는다  (p.8)

**7. 이진 탐색 트리의 탐색과 삽입**  `자세히` `출제 점수 57` `헷갈림`

이진 탐색 트리는 '왼쪽 < 루트 < 오른쪽'을 만족하는 트리이며, 탐색·삽입은 O(h)이다 (p.20). 탐색은 '루트부터 시작, 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다' (p.12). 코드에서는 n이 None이면 None을 반환하고, key == n.data이면 n을 반환하며, key < n.data이면 왼쪽, 아니면 오른쪽으로 search_bst를 재귀 호출한다 (p.12).

삽입은 '탐색이 실패한 위치(None)에 새 노드를 붙인다'이며, 그래서 '항상 단말 노드로 삽입'된다 (p.12). 코드에서는 r이 None이면 새 노드 n을 반환하고, n.data < r.data이면 r.left에, n.data > r.data이면 r.right에 insert_bst의 결과를 대입한 뒤 r을 반환한다 (p.12). 진단에서 40→60→50으로 내려가는 비교 과정은 맞았지만 위치를 '노드 50의 왼쪽 자식'이라고 명시하지 않았고, 빈 자리(None)에 새 노드를 붙인다는 결론과 항상 단말 노드로 삽입되는 이유도 빠뜨렸으므로 이 세 가지를 함께 써야 한다 (p.12). 교수님은 '삽입 순서를 주고 트리를 그리라는 문제도 자주 나와요.'라고 강조했다 (p.19).

탐색과 삽입의 시간 복잡도는 트리의 높이 h에 비례하여 O(h)이고, 균형이 잡히면 O(log n), 편향되면 O(n)이다 (p.12).

**핵심**

- 탐색: 루트부터 시작, 키가 작으면 왼쪽, 크면 오른쪽으로 내려간다
- 삽입: 탐색이 실패한 위치(None)에 새 노드를 붙인다 → 항상 단말 노드로 삽입
- 삽입 위치는 '노드 ○○의 왼쪽(오른쪽) 자식'처럼 명시한다
- 시간 복잡도 O(h): 균형이 잡히면 O(log n), 편향되면 O(n)
- 삽입 순서가 주어지면 앞에서부터 하나씩 루트에서 비교하며 내려가 트리를 그린다 (p.19 연습문제 3)

**자주 하는 실수**

- 삽입 위치를 '50 아래 왼쪽이 비어 있다'고만 쓰고 '노드 50의 왼쪽 자식'이라고 명시하지 않는다
- 빈 자리(None)에 새 노드를 붙인다는 결론과 항상 단말 노드로 삽입된다는 이유를 빠뜨린다

**교수님 말**

**9. 힙의 정의와 최대 힙·최소 힙**  `자세히` `출제 점수 27` `모름`

힙(heap)은 완전 이진 트리이면서, 모든 노드가 힙 조건을 만족하는 트리다 (p.14). 최대 힙은 부모 ≥ 자식이어서 루트가 최댓값이고, 최소 힙은 부모 ≤ 자식이어서 루트가 최솟값이다 (p.14).

힙 조건은 부모와 자식 사이에서만 따지므로 형제 사이의 순서는 없다(정렬된 것이 아님) (p.14). 교수님은 '주의할 건 형제끼리는 순서가 없다는 거예요.'라고 강조했다 (p.14). 예를 들어 최대 힙 배열 [93, 80, 75, 50, 62, 70, 33]에서 80의 두 자식 50과 62는 형제이고, 50이 62보다 작아도 최대 힙 조건에는 문제가 없다(p.14 그림).

힙은 완전 이진 트리이므로 배열로 표현하며, 부모 i의 자식은 2i, 2i+1이다 (p.14). 위 배열은 [0]을 비워 두고 [1]부터 93, 80, 75, 50, 62, 70, 33 순서로 저장한 것이다(p.14 그림). 힙 삽입은 마지막에 넣고 업힙, 힙 삭제는 루트를 꺼내고 마지막을 올려 다운힙을 하며, 둘 다 O(log n)이다 (p.20).

**핵심**

- 힙 = 완전 이진 트리 + 힙 조건(모든 노드가 만족)
- 최대 힙: 부모 ≥ 자식 → 루트가 최댓값 / 최소 힙: 부모 ≤ 자식 → 루트가 최솟값
- 형제 사이의 순서는 없다. 힙은 정렬된 것이 아니다
- 배열 표현: 부모 i → 자식 2i, 2i+1 ([0]은 비우고 [1]부터 저장)
- 삽입 = 마지막에 넣고 업힙, 삭제 = 루트 꺼내고 마지막을 올려 다운힙, 둘 다 O(log n)

**자주 하는 실수**

- 힙 조건을 형제 사이에도 적용해 형제끼리 순서가 있다고 착각한다. 힙 조건은 부모와 자식 사이에서만 따지며, 교수님도 형제끼리는 순서가 없다는 점을 주의하라고 했다
- 힙을 정렬된 트리로 오해한다. 최대 힙은 부모 ≥ 자식이라 루트만 최댓값일 뿐, 전체가 정렬된 것은 아니다

**교수님 말**

- “오늘의 핵심이에요.”
- “주의할 건 형제끼리는 순서가 없다는 거예요.”

근거 페이지  (p.14) (p.20)

**10. 힙의 삽입 연산**  `자세히` `출제 점수 100` `앎`

힙은 완전 이진 트리 + 힙 조건이며 배열로 표현한다 (p.20). 힙 삽입은 '마지막에 넣고 업힙'이며, 교수님은 '다시 한 번, 힙 삽입은 마지막에 넣고 업힙, 시간은 로그 n.'이라고 강조했다 (p.20).

절차는 ① 새 항목을 마지막 위치(배열의 끝)에 넣어 완전 이진 트리를 유지하고, ② 부모와 비교해 더 크면 부모와 교환하며 위로 올라가(업힙, sift-up) 힙 조건을 회복하는 것이다 (p.15). 예를 들어 [93, 80, 75, 50, 62, 70, 33]에 85를 마지막에 추가하면 50, 80과 교환하며 올라가다가 93보다 작으므로 정지하고, 결과는 [93, 85, 75, 80, 62, 70, 33, 50]이 된다(p.15 그림). 배열 기반 최대 힙 코드의 insert는 heap.append(n) 뒤에 while i != 1 and n > self.heap[i // 2] 조건으로 부모와 비교하며 올라가고, 인덱스 0은 사용하지 않는다 (p.17).

시간 복잡도는 트리 높이만큼만 올라가므로 O(log n)이다 (p.15). 연습문제 4번은 최대 힙 [ -, 90, 70, 80, 30, 50, 60 ]에 95를 삽입하는 과정을 단계별로 그리고 교환 횟수를 쓰라는 문제이며, 교수님은 '4번 5번은 꼭 풀어보세요.'와 '과정을 그림으로 그리라는 문제가 나올 수 있어요.'라고 말했다 (p.19).

**핵심**

- 삽입 = 마지막 위치(배열의 끝)에 넣고, 부모와 비교해 더 크면 교환하며 위로 올라간다 (업힙, sift-up) (p.15)
- 시간 복잡도 O(log n): 트리 높이만큼만 올라간다 (p.15)
- 힙 삽입·삭제 모두 O(log n)이며, 삭제는 루트를 꺼내고 마지막을 올려 다운힙한다 (p.20)
- 배열 기반 최대 힙: 인덱스 0은 사용하지 않고 부모는 i // 2이다 (p.17)
- 시험 대비: 삽입 과정을 단계별 그림으로 그리고 교환 횟수를 쓰는 연습을 한다 (p.19)

**자주 하는 실수**

- 삽입(마지막에 넣고 업힙)과 삭제(루트를 꺼내고 마지막을 올려 다운힙)의 방향과 순서를 혼동한다 (p.20)

**11. 힙의 삭제 연산**  `자세히` `출제 점수 86` `모름`

힙에서 삭제는 항상 루트(최댓값)를 꺼내는 것이다 (p.16). 교수님은 '삭제 과정도 시험에 나옵니다.'라고 강조했고, '삽입이랑 세트로 기억하세요.'라고 말했다 (p.16) (p.20).

① 루트를 꺼내고, 마지막 노드를 루트 자리로 옮긴다 (p.16). ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려가는데, 이를 다운힙(sift-down)이라고 한다 (p.16). 자료의 예에서는 93을 삭제한 뒤 33을 루트로 옮기고, 80, 62와 교환하며 내려가 결과가 [80, 62, 75, 50, 33, 70]이 된다(p.16 그림). 배열 코드에서는 'child += 1' 부분이 더 큰 자식을 선택하는 줄이고, last >= self.heap[child]이면 반복을 멈춘다 (p.17).

힙 삭제는 루트를 꺼내고 마지막을 올려 다운힙을 하는 과정이며, 시간 복잡도는 O(log n)이다 (p.16) (p.20). 이 개념은 진단에서 '모름'으로 표시했으므로, 교수님이 '4번 5번은 꼭 풀어보세요.'라고 한 연습문제 중 5번(최대 힙 [ -, 90, 70, 80, 30, 50, 60 ]에서 최댓값을 삭제한 뒤의 배열 쓰기)을 직접 풀어 보아야 한다 (p.19).

**핵심**

- 삭제 = 항상 루트(최댓값)를 꺼내는 것  (p.16)
- 절차 ① 루트를 꺼내고 마지막 노드를 루트 자리로 옮긴다 → ② 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려간다 (다운힙, sift-down)  (p.16)
- 시간 복잡도 O(log n)  (p.16)
- 힙 삽입 = 마지막에 넣고 업힙, 힙 삭제 = 루트 꺼내고 마지막을 올려 다운힙, 둘 다 O(log n)  (p.20)
- 연습문제 5번: [ -, 90, 70, 80, 30, 50, 60 ]에서 최댓값 삭제 후 배열 쓰기  (p.19)

**자주 하는 실수**

- 다운힙에서 두 자식 중 '더 큰 자식'과 비교해야 하는데 이 부분에서 실수가 많다는 것이 교수님의 경고다 (p.16).
- 삭제할 값은 루트(최댓값)이고, 그 자리를 채우는 것은 마지막 노드라는 순서(① 꺼내기 → 마지막 노드를 루트로 → ② 내려가기)를 헷갈리지 않아야 한다 (p.16).

**12. 우선순위 큐와 힙 구현**  `자세히` `출제 점수 51` `모름`

우선순위 큐는 '들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐'다 (p.18). 연산은 insert(item)과 remove()이며, remove()는 가장 높은 우선순위를 반환한다 (p.18). 힙은 완전 이진 트리 + 힙 조건이며 배열로 표현한다 (p.20).

힙 삽입은 마지막에 넣고 업힙하는 과정이고, 힙 삭제는 루트를 꺼내고 마지막을 올려 다운힙하는 과정이다 (p.20). 두 연산 모두 O(log n)이다 (p.20).

힙으로 구현하면 insert와 remove 두 연산 모두 O(log n)이고, 배열·연결 리스트는 둘 중 하나가 O(n)이다 (p.18). 표로 보면 정렬 안 된 배열은 삽입 O(1)·삭제 O(n), 정렬된 배열은 삽입 O(n)·삭제 O(1), 힙은 삽입 O(log n)·삭제 O(log n)이다 (p.18). 진단에서 '모름'으로 표시한 부분이므로, '힙으로 우선순위 큐를 구현하는 이유를 설명할 수 있다'는 학습 목표 (p.3)는 '두 연산 모두 O(log n)'이라는 시간 복잡도 비교로 답한다 (p.18) (p.19).

**핵심**

- 우선순위 큐: 들어온 순서가 아니라 우선순위가 높은 항목부터 나가는 큐, 연산은 insert(item)·remove()  (p.18)
- 힙 구현 이유: insert와 remove 모두 O(log n), 배열·연결 리스트는 둘 중 하나가 O(n)  (p.18)
- 정렬 안 된 배열 삽입 O(1)·삭제 O(n) / 정렬된 배열 삽입 O(n)·삭제 O(1) / 힙 O(log n)·O(log n)  (p.18)
- 힙 삽입 = 마지막에 넣고 업힙, 힙 삭제 = 루트 꺼내고 마지막을 올려 다운힙, 둘 다 O(log n)  (p.20)
- 응용: 운영체제 작업 스케줄링, 다익스트라 최단 경로, 허프만 코딩  (p.18)

**자주 하는 실수**

- 힙으로 구현하는 이유를 설명하지 못하고 넘어간다. 진단에서 '모름'으로 표시한 내용이며, 연습문제 6번은 정렬된 배열보다 유리한 이유를 시간 복잡도로 설명하라고 한다 (p.3) (p.19).
