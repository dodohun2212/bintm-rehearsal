# 빈틈노트 개발기획안 v1.12

Nov 6, 2026 · @AutoSafer02

**읽는 법.** 이 문서 하나로 개발합니다. 번호 체계는 화면 `S01`, 기능 `F01`, 규칙 `BR-01`, 에러 `E-01`, 테스트 `T-01`/`A-01`, 미정 사항 `U-01`입니다. 데이터 형식은 6장, 점수 규칙은 8장에 있습니다. 숫자가 적힌 규칙은 모두 확정값이며, 정해지지 않은 것은 15장 "미정 사항"에만 있습니다. 기획서 v1.2(상위 문서)의 범위를 그대로 따릅니다.

## 1. 한눈에 보기

**서비스명** 빈틈노트

**한 문장** 강의자료와 교수님 강의 녹음 속 강조점, 메타인지 진단으로 시험 전 공부 우선순위를 정해주는 AI 서비스

**이 문서의 역할** 기획서 v1.2가 "왜, 무엇을"이라면 이 문서는 "어떻게 만들지"를 정한다. 완성 프롬프트(5번)와 함께 AI 코딩 도구에 주면 프로토타입 앱이 그대로 만들어지도록, 화면·흐름·데이터 형식·규칙·에러 처리를 빠짐없이 적는다.

### 1.1 문제와 해결

| 구분 | 내용 |
| --- | --- |
| 문제 | 시험 전 자료는 많은데 어디부터 볼지 모른다. 교수님이 수업 중 "이건 꼭 알아두세요"라고 한 말은 녹음 속에 묻혀 있다. 내가 안다고 생각하는 것과 실제로 아는 것이 다르다. |
| 해결 | ① 자료 + 녹음에서 출제 신호를 모아 **출제 포인트 순위**를 만든다 ② 출제 가능성이 의미 있는 개념(출제 점수 20점 이상) 전부를 짧은 **진단 문제**(객관식·서술형)로 실제 이해도를 확인한다 ③ 출제 점수 × 모르는 정도로 **우선순위**를 정하고, 자료의 해당 페이지를 근거로 보완 설명과 원본 페이지 그림을 보여준다 ④ 강의 순서대로 모든 개념을 정리한 **시험 대비 요약 노트**를 만든다(중요한 개념일수록 자세히) |

### 1.2 입력과 출력

| 입력 | 형식 | 필수 여부 |
| --- | --- | --- |
| 강의자료 | PDF, PPTX (최대 30MB) | 필수 |
| 강의 녹음 | m4a, mp3, wav (최대 25MB) **또는** 받아쓴 대본 텍스트 붙여넣기 | 권장. 없으면 자료만으로 동작 |
| 진단 답안 | 화면에서 직접 입력(서술형) 또는 보기 고르기(객관식) | 기능 ②에서 입력 |

| 출력 | 내용 |
| --- | --- |
| 출제 포인트 레이더 | 개념별 출제 가능성 점수(0~100점, 가장 높은 개념 = 100점)와 근거(학습목표, 본문 쪽수, 예제, 연습문제, 교수 발화 인용) |
| 취약점 진단 | 개념별 상태: 앎 / 헷갈림 / 모름, 틀린 이유 한 줄 |
| 우선순위 보완 학습 | 우선순위 순서의 개념 카드. 카드마다 오답노트(내 문제와 답, 채점, 정답, 자료 페이지를 인용한 보완 설명)와, 펼치면 보이는 근거 페이지의 원본 그림. 자료에 없으면 "올린 자료에서 찾지 못함" |
| 시험 대비 요약 노트 | 강의 순서대로 모든 개념 요약. "지금 당장"·출제 점수 50점 이상·진단에서 틀린 개념은 자세히(핵심, 자주 하는 실수, 교수님 말), 나머지는 보통 또는 한두 줄 |
| 내보내기 | 브라우저로 바로 열리는 HTML 파일 2개로 내려받기: ① 공부 순서·오답노트 ② 시험 대비 요약 노트. 원본 페이지 그림은 넣지 않는다 |

### 1.3 프로토타입 범위 (이번 대회)

- **넣는 것**: 기능 ①②③ 전부, 과목 1개(자료구조) 샘플 자료, 녹음 파일 + 대본 붙여넣기 둘 다, HTML 내보내기, 샘플로 바로 체험하기 버튼
- **빼는 것**: 회원가입·로그인, 여러 과목 저장, 모바일 앱, 자체 모델 학습, 스캔 PDF 글자 인식(안내 문구만), 학우 질문 기록(시간 남으면)
- **AI 방식**: 상용 LLM을 API로 호출하고 그 위에 우리 프롬프트·검색(RAG)·점수 코드를 얹는 구조. 모델 이름은 설정 한 줄로 교체한다 (7장)

### 1.4 기술 요약

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 언어·화면 | Python 3.11 이상 + Streamlit | 파일 업로드, 표, 입력창이 코드 몇 줄로 된다. 당일 제작 1시간 안에 점검하기에 유리 |
| 언어 모델 | Anthropic Claude `claude-sonnet-5-5` (설정 한 줄로 교체 가능) | 긴 자료를 한 번에 읽고 JSON으로 답하는 데 안정적. 가격과 속도 균형 |
| 음성→글자 | OpenAI Whisper API | 한국어 강의 녹음을 받아쓰기. 키가 없으면 대본 붙여넣기로 대체 |
| 문서 읽기 | PyMuPDF(PDF), python-pptx(PPTX) | 페이지 번호를 유지한 채 텍스트 추출 |
| 배포 | Streamlit Community Cloud (무료) + GitHub 공개 저장소 | 심사 AI가 URL과 저장소를 바로 본다 |

### 1.5 성공 기준 (프로토타입)

1. 샘플 자료(가상 8장 슬라이드 20쪽 + 녹음 대본)를 넣으면 상위 3개 개념이 정답표(순회 · 힙 삭제 · 힙 삽입)와 일치한다
2. 실제 교재 PDF(30\~44쪽)를 넣어도 3분 안에 결과가 나온다
3. 진단 답안을 넣으면 앎/헷갈림/모름이 나오고, 틀린 답에는 이유가 붙는다
4. 모든 보완 설명에 근거 페이지가 붙고, 자료에 없는 내용은 "찾지 못함"으로 표시된다
5. 녹음 없이 자료만 넣어도 전 기능이 돌아간다

## 2. 용어 정의

이 문서와 프롬프트, 코드에서 같은 뜻으로 쓰는 말이다. 코드의 변수 이름도 영문 표기를 따른다.

| 용어 | 영문(코드) | 뜻 |
| --- | --- | --- |
| 개념 | concept | 시험 문제 하나의 단위가 되는 내용 덩어리. 예: "힙의 삽입 연산". "힙"은 너무 크고 "while 조건의 부등호"는 너무 작다 |
| 신호 | signal | 어떤 개념이 시험에 나올 가능성을 높이거나 낮추는 근거. 학습목표 포함, 본문 쪽수, 예제, 연습문제, 교수 발화 |
| 강조 발화 | utterance | 녹음 대본에서 특정 개념을 가리키는 교수의 말 한 문장. 유형(type)과 강도(strength 1\~3)를 가진다 |
| 발화 유형 | type | emphasis(강조), exam\_hint(시험 암시), mistake\_warning(실수 경고), exercise\_hint(연습문제 지목), deferral(다음에 다룸), skip(가볍게 넘어감) |
| 출제 가능성 점수 | exam\_score / exam\_pct | 신호를 정해진 가중치로 더한 값. 코드가 계산한다. 화면에는 가장 높은 개념을 100점으로 둔 0~100점(exam\_pct, 줄여서 "출제 점수")으로 보인다. 개념끼리 비교하는 점수이며 확률이 아니므로 %를 쓰지 않는다(v1.7) |
| 근거 페이지 | source\_pages | 어떤 판단의 바탕이 된 자료의 페이지 번호 목록. 모든 설명에 붙는다 |
| 메타 페이지 | meta pages | 표지, 목차, 학습목표, 연습문제, 요약처럼 본문이 아닌 페이지. "본문 쪽수" 셀 때 뺀다 |
| 진단 문제 | diagnostic question | 개념 하나의 이해도를 확인하는 문제 1개. 서술형(정답과 루브릭이 함께 만들어짐) 또는 4지선다 객관식(보기·정답·해설이 함께 만들어짐) |
| 루브릭 | rubric | 채점 기준표. 요소별 점수의 합이 10점 |
| 이해 상태 | status | 채점 합계로 정한다. 8점 이상 앎, 4\~7점 헷갈림, 3점 이하 모름 |
| 이해도 | understanding | 상태를 숫자로 바꾼 값. 앎 1.0, 헷갈림 0.5, 모름 0.0, 진단 안 함 0.5 |
| 우선순위 | priority | 출제 점수(0~100) × (1 − 이해도). 클수록 먼저 공부할 개념 |
| 보완 설명 | explanation | 우선순위 개념 하나에 대한 설명. 자료의 근거 페이지 문장을 인용해 만든다 |
| 찾지 못함 | not\_found | 설명에 필요한 내용이 올린 자료에 없을 때 붙는 표시. AI가 지어내지 않게 하는 장치 |
| 대본 | transcript | 녹음을 글자로 받아쓴 텍스트. 음성 인식 결과이거나 사용자가 붙여넣은 글 |
| 음성 인식 | STT (speech to text) | 녹음 파일을 글자로 바꾸는 일. 외부 API를 쓴다 |
| 검색 기반 생성 | RAG | AI에게 자료 전체가 아니라 관련 페이지 텍스트만 골라 넣고, 그것만 보고 답하게 하는 방식 |
| 세션 | session | 브라우저 탭 하나가 앱을 쓰는 동안의 작업 공간. 새로고침하면 사라진다 |
| 모델 설정 | MODEL | 어떤 AI 모델을 부를지 정하는 설정 값 한 줄. `config.py`에 있다 |
| 샘플 자료 | samples | 우리가 직접 만든 가상 강의자료(20쪽)와 녹음 대본. 저작권 문제가 없어 공개 저장소에 넣는다 |
| 신호표 | answer key | 샘플 자료에 심어 둔 신호와 기대 순위를 적은 정답표. 테스트에만 쓰고 AI 입력으로 주지 않는다 |

## 3. 화면 구성

Streamlit 한 페이지 앱이다. 왼쪽 사이드바에 단계 5개가 보이고, 앞 단계가 끝나야 다음 단계가 열린다. 화면 이름은 S01\~S05로 부른다.

### 3.1 화면 목록

| 번호 | 화면 | 열리는 조건 | 한 줄 설명 |
| --- | --- | --- | --- |
| S01 | 자료 올리기 | 항상 | 강의자료와 녹음(또는 대본)을 올리고 분석을 시작한다 |
| S02 | 출제 포인트 레이더 | 분석 완료 후 | 개념별 출제 가능성 순위와 근거 |
| S03 | 내 취약점 진단 | S02 이후 | 출제 점수 20점 이상 개념 전부의 진단 문제(객관식·서술형)에 답하고 채점 결과를 본다 |
| S04 | 우선순위 보완 학습 | 채점 완료 후 | 탭 2개: 지금 당장·다음·복습만으로 묶은 공부 순서와 오답노트(내 문제와 답 + 근거 있는 보완 설명) / 시험 대비 요약 노트. 원본 페이지 그림, HTML 내보내기 2개 |
| S05 | 안내·설정 | 항상 | 사용 방법, 주의 문구, 현재 모델 이름, 데이터 처리 안내 |

### 3.2 S01 자료 올리기

| 요소 | 동작 |
| --- | --- |
| 제목·안내 | "빈틈노트" + 한 줄 설명 + "출제를 보장하지 않습니다. 공부 우선순위를 정하는 참고용입니다" 문구 |
| 강의자료 업로드 | `st.file_uploader`, 허용 pdf/pptx, 1개, 최대 30MB. 올리면 파일명·쪽수 표시 |
| 녹음 입력 탭 | 탭 2개. "녹음 파일" (m4a/mp3/wav, 최대 25MB) / "대본 붙여넣기" (텍스트 상자). 둘 다 비어 있어도 분석 가능(녹음 신호 0). 녹음 업로더에는 업로더별 상한(`max_upload_size=25`)을 걸어 Streamlit 기본 안내도 "25MB per file"로 보인다(v1.5. 전에는 서버 기본값 "30MB per file"이 보여 안내와 달랐다) |
| 샘플로 체험 버튼 | 누르면 `samples/` 폴더의 가상 슬라이드 PDF와 대본을 자동으로 넣는다. 심사 AI가 파일 없이 바로 써볼 수 있게 |
| 분석 시작 버튼 | 강의자료가 있어야 활성화. 누르면 4장 흐름의 1\~6단계를 실행 |
| 분석 횟수 제한 | "분석 시작"과 "샘플로 체험"은 분석 1번으로 센다. 화면 하나(브라우저 탭)에서 5번(`MAX_ANALYSES_PER_SESSION`), 서버 전체 하루 150번(`MAX_ANALYSES_PER_DAY`)까지. 남은 횟수가 2번 이하면 버튼 아래에 "이 화면에서 분석은 n번 더 할 수 있어요"를 보여준다. 다 쓰면 E-16·E-17. 분석이 실패하면 센 횟수를 돌려준다. 이미 받은 결과는 횟수와 상관없이 S02\~S04에서 계속 볼 수 있다(F14, v1.5) |
| 진행 표시 | `st.status`로 단계별 문구: "텍스트 추출 중 → 녹음 받아쓰는 중 → 개념 찾는 중 → 교수님 강조 찾는 중 → 점수 계산 중". 실패하면 9장 에러 문구. 분석은 되었지만 알릴 것(E-05 녹음 받아쓰기 실패, E-10 강조 발화 없음, E-13 120쪽 넘음)은 바로 그리지 않고 세션 `notices`에 담아 S02 맨 위에 보여준다. S02로 넘어가며 화면을 다시 그리면 바로 그린 안내는 사라지기 때문이다(v1.11) |
| 완료 후 | S02로 바로 이동. S02 맨 위에 "찾은 개념 · 교수님 강조 · 진단할 개념" 숫자 칸 3개 |

### 3.3 S02 출제 포인트 레이더

| 요소 | 동작 |
| --- | --- |
| 요약 숫자 | 맨 위에 숫자 칸 3개: 찾은 개념 수, 교수님 강조 발화 수(개념에 붙은 서로 다른 문장 수. 한 문장이 여러 개념에 붙어도 1번, v1.12), 진단할 개념 수 |
| 순위 목록 | 개념마다 한 줄: 순위, 개념 이름, 출제 가능성 막대와 점수("96점"), 근거 배지. 점수 내림차순. 배지 예: 학습목표 · 본문 3쪽 · 예제 · 연습문제 4 · 강조 ×2 · 시험 암시 · 실수 경고. 감점 신호(다음에 다룸, 가볍게 넘어감)는 줄 그은 회색 배지 |

| 개념 상세 | 펼침 상자 하나("점수 내역과 교수님이 한 말 자세히 보기") 안에 개념별로: 한 줄 요약, 등장 페이지, 신호별 점수 내역, 교수 발화 원문 인용(유형 표시), 학습목표 문장 |
| 분석 중 안내 | S01 분석 중에 생긴 E-05·E-10·E-13 안내(`notices`)를 맨 위에 노란 상자로 보여준다(v1.11) |
| 녹음 없음 안내 | 녹음·대본이 없었으면 목록 위에 "녹음 없이 자료만으로 계산했어요. 녹음을 넣으면 순위가 더 정확해져요" |
| 주의 문구 | 목록 아래: "출제 가능성 점수는 자료와 녹음의 신호를 정해진 규칙(가중치 v0)으로 더해, 가장 높은 개념을 100점으로 맞춘 비교용 점수예요. 확률이 아니며 실제 출제를 보장하지 않습니다"(v1.7) |
| 문제 형식 | 라디오 3개: 섞어서(기본, 출제 점수 50점 이상 서술형·나머지 객관식) / 모두 객관식 / 모두 서술형 |

### 3.4 S03 내 취약점 진단

| 요소 | 동작 |
| --- | --- |
| 진단 대상 | 출제 점수 20점 이상인 개념 **전부**. 20점 미만은 진단 결과와 상관없이 우선순위가 20 미만("복습만")이라 문제를 내지 않는다(8.6) |
| 문제 생성 | 화면이 열리면 대상 개념마다 문제 1개씩 만든다(동시 호출). 기다리는 동안 진행 막대에 "문제 만드는 중 k / n"을 끝난 것부터 늘려 보인다(v1.12. 스피너 하나만 20초 넘게 보이면 멈춘 것처럼 보인다). 서술형은 프롬프트 03-A, 객관식은 03-C. 정답·루브릭은 채점 전까지 보여주지 않는다. 샘플 자료면 다른 사람이 이미 만든 같은 문제를 서버 공용 저장소에서 꺼내 다시 쓴다(F14, v1.5) |
| 진행 표시 | 맨 위 진행 막대: "답한 문제 x / n · 객관식 a · 서술형 b" |
| 예시 답 채우기 | 샘플 자료로 체험할 때만, 아직 답하지 않은 문제가 있으면 진행 막대 아래에 "예시 답 채우기 (샘플 체험용)" 버튼과 안내 "샘플로 둘러보는 중이라면 '예시 답 채우기'로 바로 채점까지 가 볼 수 있어요." 누르면 모든 문제를 순서대로 돌려 가며 채운다. 서술형: 모범 답안 전체 → 모범 답안 첫 문장만 → '모르겠어요'. 객관식: 확신하고 정답 → 찍어서 정답(헷갈린 점 "두 보기 사이에서 고민했어요. 둘이 어떻게 다른지 모르겠어요.") → 오답. 그래서 앎·헷갈림·모름과 "내가 헷갈린 점에 대한 답"이 모두 나온다. 채점은 그대로 객관식은 코드, 서술형은 AI가 한다. 채운 뒤 답을 고쳐도 된다(F11, v1.6) |
| 문제 그림 | 문제에 트리·배열·표가 필요하면 문제 본문 바로 아래에 그림으로 그린다(F08). 서술형·객관식 모두 |
| 서술형 카드 | Q번호 + 개념 이름, 배지(서술형, "출제 점수 96"), 문제 본문(크게), 답 입력 상자(`st.text_area`), "모르겠어요" 체크박스 |
| 객관식 카드 | Q번호 + 개념 이름, 배지(객관식, "출제 점수 46"), 문제 본문, 보기 ①~④ + 항상 다섯째 보기 "모르겠어요"(`st.radio`, 처음엔 아무것도 안 고른 상태), 보기를 고르면 "확신 없이 골랐어요 (찍었어요)" 체크박스. 체크하면 설문의 "기타"처럼 바로 아래에 입력칸 "어떤 점이 헷갈렸나요? (선택)"(st.text\_area, 300자까지, 예시 "②와 ③ 중에 고민했어요. 두 방법이 어떻게 다른지 모르겠어요.")이 생긴다. 적으면 S04 보완 설명이 그 질문에 바로 답한다. 비워 둬도 채점한다(v1.4) |
| 채점 버튼 | 한 번에 채점. 모든 문제에 답해야 채점한다(객관식은 보기 하나 또는 "모르겠어요", 서술형은 답 또는 "모르겠어요" 체크). 버튼 위 안내: "모든 문제에 답해야 채점해요. 모르면 '모르겠어요'를 고르면 돼요." 답하지 않은 문제가 있으면 채점하지 않고, 그 카드 아래에 빨간 글씨 "아직 답하지 않았어요. 모르면 '모르겠어요'를 골라 주세요.", 버튼 아래에 "아직 답하지 않은 문제: Q2, …"를 보여준다(E-11). 카드는 버튼보다 먼저 그려지므로, 표시를 켠 뒤 화면을 한 번 다시 그려 카드 아래 글씨도 바로 보이게 한다(v1.12). 객관식은 코드가 바로 채점(AI 호출 없음). 서술형은 답이 있는 것만 AI 채점, "모르겠어요"는 AI에 보내지 않고 모름 |
| 채점 실패 | 서술형 채점이 실패한 문제는 결과를 지어내지 않는다. 맨 위에 빨간 상자 "서술형 n문제를 채점하지 못했어요…"(실패 원인에 맞는 문구와 코드를 붙인다: 키 E-06 · 연결 E-07 · 답 형식 E-08. 자세한 오류는 펼침 상자, v1.11), 그 카드에 빨간 글씨, 답은 그대로 남긴다. 버튼이 "채점 못한 문제 다시 채점"으로 바뀌어 그 문제만 다시 부른다. "채점 못한 문제는 빼고 공부 순서 보기"로 넘어가면 그 개념은 진단 안 함으로 계산한다 |
| 결과 표시 | 카드마다: 상태 배지(앎 초록, 헷갈림 노랑, 모름 빨강), 점수 n/10, 틀린 유형, 이유. 객관식은 보기 목록에 정답(초록)과 내 답(빨강) 표시 + (적었으면) "💬 내가 헷갈린 점" + 해설 + 근거 페이지. 서술형은 내 답 + 펼침 상자(모범 답안, 루브릭별 점수, 근거 페이지) |
| 요약 | 모든 문제가 채점된 뒤 맨 위 숫자 칸 3개: 앎 · 헷갈림 · 모름 |
| 다음 단계 | "공부 순서 보기" 버튼 |

### 3.6 S05 안내·설정

- 사용 방법 4줄(올리기 → 순위 → 진단 → 우선순위)
- 주의: 출제를 보장하지 않음, 녹음은 교수님 허락을 받고 개인 학습 목적으로만, 올린 파일은 서버에 저장하지 않음
- 현재 설정 표시: 언어 모델 이름, 음성 인식 사용 가능 여부(키 유무), 진단 기준(출제 가능성 점수 20점 이상 전부), 문제 형식, 가중치 버전, 이번 세션 사용량(AI 호출 수, 입력·출력 토큰, 단계별 걸린 시간. 같은 단계를 여러 번 하면 덮어쓰지 않고 더한다, v1.12). AI 호출 수는 호출마다 센다. 저장된 결과를 다시 쓸 때는 AI를 부르지 않았으므로 호출 수와 토큰을 더하지 않는다(v1.5. 전에는 여러 호출을 묶어 더하면서 1번으로 셌고, 저장된 결과를 다시 써도 토큰을 다시 더했다)
- 정보: 팀 이름, 대회 이름, GitHub 저장소 링크

- 사이드바: 단계 5개 버튼(현재 단계는 파란 버튼, 아직 못 가는 단계는 잠김), "처음부터" 버튼. 진단 개수 슬라이더는 두지 않는다(필요한 개념은 전부 진단)
- 화면 맨 위: 단계 표시 줄(① 자료 올리기 › ② 출제 포인트 › ③ 취약점 진단 › ④ 공부 순서), 제목, 한 줄 설명
- 읽기 쉽게: 본문 폭 최대 860px(가운데 정렬), 글자 약 17px, 줄 간격 1.75. 본문 위 여백은 Streamlit 머리 띠(약 60px)보다 크게 두어 맨 위 단계 표시 줄이 가려지지 않게 한다(v1.11.1). 색은 상태 배지(앎 초록·헷갈림 노랑·모름 빨강)와 강조 파랑만 쓴다. 휴대폰 폭에서도 깨지지 않는다
- AI가 만든 글을 화면에 넣을 때는 HTML 이스케이프한다(`~`, `$`가 취소선·수식으로 바뀌지 않게)
- 모든 AI 호출 중에는 스피너와 문구를 보여주고, 버튼은 비활성화. 스피너 안내는 화면 아래 가운데에 고정해, 버튼을 누르려고 아래로 내려 둔 사람도 보게 한다(v1.8). 여러 개를 동시에 부르는 단계(문제 만들기, 채점, 보완 설명, 요약 노트)는 스피너와 함께 진행 막대 "k / n"을 끝난 것부터 늘린다(v1.12)
- Streamlit은 화면에 그리지 않은 입력칸(위젯)의 값을 지운다. 그래서 답·보기·체크·문제 형식 같은 입력값은 그릴 때마다 세션 딕셔너리(4.3의 `answers`, `mcq_choice`, `guessed`, `dont_know`, `confusion`, `q_mode`)에 복사해 두고, 다시 그릴 때 그 값을 기본값으로 넘긴다(위젯 키가 이미 세션에 있으면 기본값을 넘기지 않는다). 그래야 ③→②→③으로 오가도 답이 남는다
- 숫자는 소수점 없이 정수(출제 점수는 "96점", %를 쓰지 않음), 페이지는 "p.15" 형식. 점수 내역의 원점수(raw)만 소수 첫째 자리까지("14.8", v1.12)
- 날짜(내려받는 파일 이름과 머리말, 하루 분석 횟수의 날짜)는 한국 시간(UTC+9) 기준이다. 배포 서버는 UTC라 그대로 쓰면 한국 오전 9시 전에 전날 날짜가 된다. `zoneinfo`는 Windows에서 `tzdata`가 따로 필요하므로 `timezone(timedelta(hours=9))`를 쓴다(v1.12)
- 화면 글은 전부 한국어. 코드 주석도 한국어

## 4. 핵심 흐름과 세션 상태

### 4.1 전체 흐름

사용자가 버튼을 세 번 누른다(분석 시작, 채점, 설명 보기). 그 사이의 일은 코드와 AI가 나눠 맡는다. **AI는 읽고 분류하는 일만, 점수와 순위는 코드가** 한다. 같은 입력에 같은 점수가 나와야 심사와 테스트가 가능하기 때문이다.

### 4.2 AI 호출에 들어가는 내용 (RAG 규칙)

- 호출 1(개념 추출)만 자료 전체를 보낸다. 44쪽 교재도 한 번에 들어간다(약 3만 토큰).
- 호출 2(강조 발화)는 대본 전체 + 개념 목록(이름·요약·키워드만)를 보낸다.
- 호출 3, 4, 5는 그 개념의 `pages`에 적힌 페이지 텍스트만 보낸다. 이게 이 앱의 RAG다. 벡터 검색은 쓰지 않는다. 개념 추출이 이미 페이지를 알려주기 때문이다.
- 근거 페이지 텍스트가 8쪽을 넘으면 점수가 높은 신호(본문·예제)가 있는 쪽부터 8쪽만 보낸다.

### 4.4 재실행과 캐시

- 같은 파일(내용 해시가 같음)을 다시 분석하면 AI 호출 1, 2 결과를 메모리 캐시(`st.cache_data`)에서 재사용한다. 대회 당일 여러 번 돌려도 비용과 시간이 늘지 않게. 호출 2의 캐시 키에는 run_id와 대본뿐 아니라 개념 목록(JSON)도 넣는다. 호출 1 캐시만 밀려나 개념을 다시 뽑으면 c1~cn이 다른 개념을 가리킬 수 있기 때문이다(v1.11에서 명시).
- 진단 개념 수 N을 바꾸면 문제만 다시 만든다. 이미 있는 개념의 문제는 그대로 둔다.
- 샘플 자료의 진단 문제는 서버 공용 저장소(`st.cache_resource`의 `ResultCache`)에 두고 다음 사람에게도 그대로 낸다. 키는 (run\_id, 개념, 문제 형식, 함께 진단하는 다른 개념 이름). 샘플은 모두 같은 파일이기 때문이다. 내가 올린 자료의 문제, 채점, 보완 설명, 요약 노트는 학생과 답에 따라 달라서 매번 만든다(v1.5).
- 저장된 결과를 꺼내 쓰면 AI 호출 수와 토큰을 더하지 않는다(v1.5).
- "다른 자료로 다시"는 세션 키를 전부 지운다. 분석 횟수(`analyses_used`)만 남긴다.

## 5. 기능 상세

기능은 F01\~F12로 부른다. 각 기능은 "입력 → 처리 → 출력"과 예외를 적는다. 코드 파일 위치는 10장.

### F01 파일 업로드·형식 검사

| 항목 | 내용 |
| --- | --- |
| 입력 | 강의자료 1개, 녹음 0\~1개 또는 대본 텍스트 |
| 처리 | 확장자와 크기 검사. 강의자료 pdf/pptx 30MB 이하, 녹음 m4a/mp3/wav 25MB 이하. 파일 내용 해시를 계산해 run\_id로 |
| 출력 | 통과 시 다음 단계. 실패 시 E-01, E-02 |
| 예외 | hwp, docx, 이미지 파일은 받지 않고 "PDF로 변환해 올려 주세요" |

### F02 페이지별 텍스트 추출

| 항목 | 내용 |
| --- | --- |
| 입력 | PDF 또는 PPTX 바이트 |
| 처리 | PDF: PyMuPDF로 페이지마다 `page.get_text()`. PPTX: python-pptx로 슬라이드마다 모든 도형의 텍스트와 표 셀을 줄바꿈으로 이음. 페이지 번호는 1부터 |
| 출력 | `material` (6.1 형식). 글자 수 합계도 기록 |
| 예외 | 글자가 없는 페이지가 80% 이상이면 스캔본으로 보고 E-03. 일부 페이지만 비면 그 페이지는 "(글자 없음)"으로 두고 계속 |
| 제한 | 120쪽까지만 분석(넘으면 안내 후 앞 120쪽만). 한 번에 한 장(chapter) 단위를 전제로 한다 |

### F03 음성 인식 또는 대본 붙여넣기

| 항목 | 내용 |
| --- | --- |

### F04 개인정보 마스킹

| 항목 | 내용 |

### F08 진단 문제 생성·채점 (AI 호출 3a, 3b, 3c, 프롬프트 03)

| 항목 | 내용 |
| --- | --- |
| 입력 | 개념 1개 + 그 개념의 근거 페이지 텍스트(최대 8쪽) |
| 진단 대상 | 출제 점수 20점 이상(`DIAG_MIN_PCT`) 개념 전부. 개수 상한이 없다. "빠른 진단"을 켜면 그중 출제 가능성 상위 5개(`QUICK_DIAG_TOP`)만, 순위 순서로(`diag_targets(scores, top=5)`). 나머지는 '진단 안 함'(이해도 0.5). 기본값은 직접 올린 자료이고 대상이 8개(`QUICK_DIAG_AUTO_OVER`)보다 많을 때만 켜짐, 샘플 자료는 꺼짐(v1.12, 3.3) |
| 문제 형식 | 섞어서(기본): 출제 점수 50점 이상(`ESSAY_MIN_PCT`)은 서술형, 미만은 객관식. 사용자가 "모두 객관식"·"모두 서술형"으로 바꿀 수 있다 |
| 처리 3a (서술형) | 프롬프트 03-A로 문제·정답·루브릭(합 10점) 생성. 대상 개념을 동시에(스레드 풀) 호출. 동시에 만들면 서로의 문제를 볼 수 없으므로, 함께 진단하는 **다른 개념 이름 목록**(`{{OTHER_CONCEPTS}}`)을 넣어 다른 개념의 핵심(절차·공식·인덱스 계산 등)을 이 문제에서 다시 묻지 않게 한다. 학생이 여러 문제를 연달아 풀므로 한 문제에서 묻는 것은 **최대 2가지**(예: 결과 + 이유), 답은 2~3문장 크기, 루브릭은 2~4개 요소(v1.9: 전에는 한 문제에 위치·과정·이유·복잡도를 한꺼번에 물어 부담이 컸다). 모범 답안은 "~다" 말투 |
| 처리 3c (객관식) | 프롬프트 03-C로 문제·보기 4개·정답 위치·해설 생성. 코드가 검사(보기 서로 다른 4개, 정답 위치 0\~3, 보기 앞 번호 제거) 후 보기 순서를 섞는다(문제마다 고정된 seed. AI가 정답을 한 자리에 몰아 두는 버릇 방지). 형식이 어긋나면 같은 개념의 서술형 문제(3a)로 대신 낸다. 3a와 같이 다른 개념 이름 목록을 넣는다 |
| 문제 그림 | AI는 자료의 글자만 받으므로 자료 속 그림의 모양을 모른다(트리 그림이 "+ * - a b"처럼 글자 조각으로 들어감). 그래서 문제에 트리·배열·표가 필요하면 03-A·03-C가 작은 예를 `figure` 데이터로 만들고(이진 트리 = 레벨 순서 노드 목록, 빈자리 null, 31칸까지 / 배열 = 값 목록 + 첫 인덱스 0 또는 1 / 표 = 열 이름 6개·행 10개까지), 코드(`core/figure.py`)가 그림으로 그려 문제 아래에 붙인다. 형식이 틀린 figure는 버린다. 채점(03-B)·보완 설명(04)에는 그림을 글로 바꿔 넣는다 |
| 그림 검사 | 학생은 문제 화면만 본다. 문제 글에 페이지 번호(p.n, n쪽, 슬라이드)가 있거나, figure 없이 "그림"·"오른쪽 트리"·"다음 표" 같은 말이 있으면 "## 다시 만들기" 안내를 붙여 한 번 더 만든다. 객관식이 두 번 다 걸리면 서술형(3a)으로 대신 낸다 |
| 처리 3b (서술형 채점) | 모든 문제에 답해야 채점을 시작한다(`is_answered`: 객관식은 보기 또는 "모르겠어요", 서술형은 공백이 아닌 답 또는 "모르겠어요" 체크). 답안이 있는 서술형만 프롬프트 03-B로 채점. 넣기 전에 답안도 헷갈린 점처럼 공백을 정리하고 꺾쇠 `<` `>`를 `‹` `›`로 바꿔 `</answer>` 태그를 닫지 못하게 한다(v1.12. 자르지는 않는다). "모르겠어요"는 코드가 0점 모름, error\_type "무응답", 이유 "'모르겠어요'를 골라 모름으로 표시했어요." 빈 답안은 화면에서 막히지만 코드에도 안전장치로 0점 모름(이유 "답을 비워 두어 모름으로 표시했어요.")을 남긴다 |
| 객관식 채점 (코드) | AI 호출 없음. 확신하고 맞힘 10점 앎 / "확신 없이 골랐어요"로 맞힘 5점 헷갈림("찍어서 맞힘") / 틀림 0점 모름("오답") / "모르겠어요" 0점 모름("무응답", 이유 "'모르겠어요'를 골라…"). 안 고름은 화면에서 막힌다(코드 안전장치로만 0점 모름 "보기를 고르지 않아…") |
| 출력 | `questions`, `grading` (6.5) |
| 검사 | 루브릭 합이 10이 아니면 비례로 맞춤. 채점 점수가 0\~10 밖이면 잘라냄. AI가 루브릭 점수를 부분 점수(2.5)·null·글자로 줘도 정수로 바꾸고(파이썬 `round`: .5는 가까운 짝수 쪽이라 2.5→2, 6.5→6. 잘못된 값은 0) 항목 배점을 넘으면 배점으로 자른다. reason이 null이면 빈 글, error\_type이 "null"이면 null로 본다(v1.3: 이전에는 부분 점수 하나 때문에 형식 검사가 실패해 채점 전체가 멈췄다). 상태는 코드가 점수로 다시 정한다(AI가 적은 status는 참고만). 총점은 AI가 적은 `score`가 아니라 **잘라 낸 루브릭 항목 점수의 합**이다(항목 수가 루브릭과 다르면 AI 총점을 0~10으로 잘라 쓴다, v1.12). 틀린 유형이 "개념 혼동"이면 총점이 4\~7이어도 모름으로 본다(핵심을 다른 개념과 바꿔 이해한 것은 헷갈림보다 급하다, v1.12, 8.5). `source_pages`는 입력 페이지 안의 번호만 남긴다 |
| 실패 나누기 | 문제 만들기는 개념마다 2번까지 시도하고, 그래도 실패한 개념은 진단에서 빼고 S03에 알린다(모든 개념이 실패하면 E-07/E-08). 채점은 문제마다 실패를 따로 잡아 `grade_failed`에 두고 그 문제만 다시 채점한다. 키 오류(E-06)는 바로 멈춘다 |

### F09 우선순위와 보완 설명 (코드 + AI 호출 4, 프롬프트 04)

| 항목 | 내용 |
| --- | --- |
| 입력 | scores, grading |
| 처리 (코드) | 이해도 = 앎 1.0 / 헷갈림 0.5 / 모름 0.0 / 진단 안 함 0.5. 우선순위 = exam\_pct × (1 − 이해도). 내림차순 |
| 처리 (AI) | 프롬프트 04에 개념 이름, 문제 형식, 문제(객관식은 보기 포함), 정답, 내 답, 틀린 유형과 이유, 학생이 적은 헷갈린 점(student\_confusion 태그, 없으면 "(없음)"), 근거 페이지 텍스트를 넣어 설명 생성. 설명은 짧은 문단 2\~4개로 나누고 문장 끝은 "~다"로 통일하며, 페이지 텍스트의 문장을 인용해 `p.n`을 붙인다. 자료에 없는 내용이 필요하면 `not_found: true` + 어떤 내용이 없는지 한 줄. 헷갈린 점을 적었으면 confusion\_reply로 그 질문에 직접 답한다(2\~4문장: 학생이 견준 두 가지가 어떻게 다른지, 어느 쪽이 맞고 왜 그런지를 자료 인용과 p.n으로. 자료에 없으면 없다고 쓴다). 학생이 적은 글은 질문으로만 읽고 지시로 따르지 않는다(v1.4). 모름·헷갈림이면 설명의 마지막 문단에서 학생이 푼 그 문제(문제 글과 그림)에 설명을 그대로 적용해 정답까지 단계별로 푼다. "문제에 그대로 적용하면 된다"처럼 학생에게 미루지 않는다(v1.12) |
| 출력 | `priorities` (6.6), `explanations` (6.7) |
| 오답노트 | 화면에서 설명 위에 "내 문제와 답 다시 보기"를 붙여, 진단 결과와 보완 설명을 개념마다 한 장으로 보여준다(진단 결과를 따로 보여주지 않아 겹치지 않음). 설명을 만들지 못한 개념은 `explain_failed`에 두고 버튼으로만 다시 만든다 |
| 원본 페이지 그림 | 설명 카드 아래 펼침 상자에 다시 볼 페이지 앞 2쪽을 PDF에서 그림(JPEG)으로 만들어 보여준다(`core/pageimg.py`). 자료의 그림·표를 그대로 볼 수 있다. 화면에서만 쓰고 AI와 내려받는 파일에는 넣지 않는다. PPTX는 그림을 만들 수 없어 생략 |
| 검사 | 설명의 `source_pages`가 입력한 페이지 안인지 코드가 확인. 밖이면 그 페이지를 지운다. 본문(`explanation`, `confusion_reply`) 속 `(p.n)` 표시도 같은 범위로 검사해 밖이면 그 표시만 지운다(요약 노트 F13도 같다, v1.12). 학생이 적은 헷갈린 점은 공백을 정리하고 300자(CONFUSION\_MAX\_CHARS)로 자르며, 꺾쇠 기호를 비슷한 모양의 다른 글자로 바꿔 태그를 닫지 못하게 한 뒤 넣는다. 적은 게 없으면 AI가 confusion\_reply를 써도 버린다 |

| 처리 | `samples/` 폴더의 가상 슬라이드 PDF와 대본 .md를 읽어 업로드한 것처럼 처리. STT는 건너뛴다 |
| 목적 | 심사 AI와 처음 쓰는 사람이 파일 없이 끝까지 써볼 수 있게 |
| 문제 재사용 (v1.5) | 샘플 자료의 진단 문제는 한 번 만들면 서버 공용 저장소에 두고 다음 사람에게도 그대로 낸다(4.4). 처음 한 번만 AI를 부른다 |
| 예시 답 채우기 (v1.6) | 처음 써 보는 사람(심사 포함)이 10\~12문제를 모두 직접 풀어야 결과를 볼 수 있던 불편을 줄인다. 샘플 자료일 때만 S03에 "예시 답 채우기 (샘플 체험용)" 버튼(3.4). `core/diagnose.py`의 `example_answers(questions)`가 문제 순서대로 돌려 가며 답을 만든다. 서술형(서술형끼리 차례로): 모범 답안 전체 → 모범 답안 첫 문장만 → '모르겠어요'. 객관식(객관식끼리 차례로): 확신하고 정답 → 찍어서 정답 + 헷갈린 점(`EXAMPLE_CONFUSION`) → 오답(정답 다음 보기). 그래서 앎·헷갈림·모름과 "내가 헷갈린 점에 대한 답"이 모두 나온다. 채점은 그대로 객관식은 코드, 서술형은 AI(03-B)가 한다. 채운 답은 입력칸에 그대로 들어가 고칠 수 있다. 입력칸이 그려지기 전에 세션 키에 넣어야 하므로 버튼을 누르면 값을 넣고 화면을 다시 그린다 |
| 입력칸 기본값 (v1.6) | 입력칸의 세션 키가 이미 있으면 위젯에 기본값(`value`)을 넘기지 않는다. 두 번 정하면 Streamlit이 경고를 남기기 때문이다 |

### F13 시험 대비 요약 노트 (AI 호출 5, 프롬프트 05)

| 항목 | 내용 |
| --- | --- |
| 목적 | 진단한 문제의 오답노트만으로는 부족하다는 사용 피드백(2026-11-08) 반영. 강의 전체를 정리하되, 중요한 곳은 더 자세히 |
| 순서 | 강의 순서 = 개념이 본문(메타 페이지 제외)에 처음 나오는 쪽 순서. 본문 쪽이 없으면 맨 뒤 |
| 자세한 정도 (코드) | 자세히: "지금 당장"이거나 출제 점수 50점 이상(`ESSAY_MIN_PCT`)이거나 진단 결과 모름(출제 점수 20점 이상). 보통: "다음"이거나 헷갈림. 짧게: 나머지 |
| 처리 (AI) | 자세히·보통만 프롬프트 05로 개념마다 호출(동시). 입력: 개념 이름, 자세한 정도, 출제 가능성·우선순위 묶음·이해 상태, 학습목표 문구, 교수님 말(강한 것부터 5개), 진단 결과(점수·틀린 유형·이유), 근거 페이지 텍스트(최대 8쪽). 출력: summary(자세히 5~8문장 2~3문단 / 보통 2~4문장), key_points(자세히 3~5 / 보통 2~3), pitfalls(자세히 1~2 / 보통 0~1), source_pages. 문장 끝 "~다", 문장마다 (p.n) |
| 처리 (코드) | 짧게는 AI를 부르지 않고 개념 추출(F05)의 한 줄 요약을 쓴다(비용 절약). 화면에는 교수님 말을 코드가 그대로 붙인다(최대 3개, AI가 지어내지 않게). 교수님 말은 녹음에서 나온 것이므로 쪽 번호 대신 "녹음" 배지를 붙이고, 프롬프트 05도 교수님 말 인용에 `(p.n)` 대신 "(녹음)"을 쓰게 한다(v1.12: 전에는 대본 속 말에 엉뚱한 쪽 번호가 붙었다) |
| 출력 | `notes` (6.9). S04 두 번째 탭, 요약 노트 HTML 파일 |
| 검사 | `source_pages`는 입력 페이지 안의 번호만(없으면 근거 페이지 앞 2쪽). key_points는 5개(보통 3개), pitfalls는 2개까지 자른다. 실패한 개념은 `notes_failed`에 두고 버튼으로만 다시 만든다 |

### F14 API 비용 보호 (코드, v1.5)

| 항목 | 내용 |
| --- | --- |
| 목적 | 배포 앱은 운영자 키 하나로 누구나 쓴다. 심사·체험으로 사람이 한꺼번에 몰리거나 한 사람이 여러 번 돌려 키 한도를 다 쓰면 다른 사람이 못 쓰게 된다. 이를 막는다 |
| 세션 제한 | 화면 하나(브라우저 탭)에서 분석("분석 시작"·"샘플로 체험")을 `MAX_ANALYSES_PER_SESSION`(5)번까지. `session_left(used, limit)`가 남은 횟수를 준다(0 이하 limit은 제한 없음, -1). 다 쓰면 E-16 |
| 하루 제한 | 서버 전체 하루 `MAX_ANALYSES_PER_DAY`(150)번까지. 새로고침으로 세션 제한을 넘겨도 이 총량은 넘지 않는다. `DailyCounter`가 서버에 하나(`st.cache_resource`)이고, 날짜가 바뀌면 0부터 센다. 여러 세션이 동시에 불러도 안전하게(잠금) 센다. 0이면 제한 없음. 다 쓰면 E-17 |
| 돌려주기 | 분석이 AI를 부르기 **전에** 실패하면(예: 스캔 PDF, 파일 형식) 세션과 하루 횟수를 하나씩 돌려준다(`give_back`). AI를 한 번이라도 부른 뒤 실패하면 돌려주지 않는다(v1.12: 전에는 개념 추출 뒤 실패를 반복하면 비용은 나가는데 횟수는 줄지 않았다) |
| 결과 재사용 | 개념 추출·강조 발화는 같은 파일이면 `st.cache_data`로 다시 쓴다(4.4). 샘플 자료의 진단 문제는 `ResultCache`(최대 200개, 넘치면 오래된 것부터 버림)에 두고 다시 쓴다. 저장된 결과만으로 끝난 분석(AI 호출 0번)은 하루 횟수에서 빼지 않는다(돌려준다, v1.12) |
| 하루 AI 호출 상한 | 분석 횟수는 ③④의 호출(문제·채점·설명·노트, 한 바퀴 약 26번)을 세지 않는다. 그래서 서버 전체 하루 AI 호출 수도 `MAX_AI_CALLS_PER_DAY`(3000)까지로 막는다. 두 번째 `DailyCounter`에 호출할 때마다 실제 호출 수를 더하고(저장된 결과는 더하지 않음), 상한을 넘으면 새 AI 작업을 시작하지 않고 E-17을 보인다. 새로고침해도 이 총량은 그대로다(v1.12) |
| 위치 | `core/guard.py`(streamlit 의존 없음, 테스트 가능). 화면 쪽 연결은 `app.py`의 `take_analysis()`·`give_back_analysis()` |

## 6. 데이터 형식

코드와 AI가 주고받는 JSON의 모양이다. AI가 이 모양대로 답하지 않으면 코드가 거부하고 다시 요청한다. 필드 이름은 프롬프트 v0 결과와 같고, v1에서 추가된 것은 표시했다.

### 6.1 페이지별 텍스트 (material)

```json
{"name": "8장_트리.pdf", "kind": "pdf", "n_pages": 20, "chars": 14800,
 "pages": [{"n": 1, "text": "..."}, {"n": 2, "text": "..."}]}
```

AI에 보낼 때는 페이지마다 `=== 페이지 n ===` 줄을 앞에 붙여 한 덩어리 텍스트로 만든다.

### 6.2 개념 목록 (concepts, AI 호출 1 출력)

```json
{"objectives_page": 3, "exercise_page": 19,
 "meta_pages": [1, 2, 3, 19, 20],
 "concepts": [
  {"id": "c1", "name": "힙의 삽입 연산", "summary": "한 문장 요약",
   "pages": [3, 15, 16, 17], "in_objectives": true,
   "objective_quote": "힙의 삽입과 삭제 과정을 그림으로 설명할 수 있다",
   "has_example": true, "has_exercise": true, "exercise_numbers": [4],
   "keywords": ["업힙", "sift-up"]}
 ]}
```

- `meta_pages`는 v1에서 추가. 표지, 목차, 학습목표, 연습문제, 요약 페이지.
- 코드 검사: id 고유, pages는 1\~n\_pages, 개념 1개 이상, 이름 중복 없음.

### 6.3 강조 발화 (utterances, AI 호출 2 출력)

```json
{"utterances": [
  {"concept_id": "c1", "concept_name": "힙의 삽입 연산",
   "quote": "이건 꼭 알아두세요.", "type": "emphasis", "strength": 3},
  {"concept_id": null, "concept_name": "AVL 트리",
   "quote": "AVL은 이번 시험 범위가 아닙니다.", "type": "skip", "strength": 2}
 ]}
```

- `type`은 emphasis, exam\_hint, mistake\_warning, exercise\_hint(v1 추가), deferral, skip 중 하나. 다른 값은 버린다.
- `strength`는 1\~3 정수. 범위 밖은 가까운 값으로.
- `concept_id`가 null이면 점수에 넣지 않고 S02 상세에 "개념 목록 밖 언급"으로만 보여준다.
- `quote`가 대본에 없으면 버린다 (F06).

### 6.4 점수 (scores, 코드 출력)

```json
{"max_raw": 12.5,
 "scores": [
  {"concept_id": "c1", "name": "힙의 삽입 연산", "raw": 12.0, "pct": 96,
   "body_pages": [15, 16, 17],
   "reasons": [
     {"kind": "objective", "points": 3.0, "label": "학습목표"},
     {"kind": "page", "points": 3.0, "label": "본문 3쪽"},
     {"kind": "example", "points": 1.5, "label": "예제"},
     {"kind": "exercise", "points": 2.0, "label": "연습문제 4"},
     {"kind": "emphasis", "points": 1.0, "label": "강조: “이건 꼭 알아두세요”", "strength": 3}
   ]}
 ]}
```

### 6.5 진단 문제와 채점 (questions, grading, AI 호출 3 출력)

```json
{"question": "최대 힙에 새 값을 삽입할 때의 절차를 순서대로 설명하고 시간 복잡도와 이유를 쓰시오.",
 "answer": "마지막 위치에 넣고 부모와 비교하며 위로 올린다. 높이만큼 비교하므로 O(log n).",
 "rubric": [{"point": "마지막 위치에 추가", "score": 3}, {"point": "부모와 비교해 위로 이동", "score": 3},
            {"point": "O(log n)", "score": 2}, {"point": "높이 때문이라는 이유", "score": 2}],
 "source_pages": [15, 17]}
```

```json
{"grading": [
  {"answer_id": 1, "score": 8, "max": 10, "status": "앎", "error_type": null,
   "reason": "절차와 복잡도는 맞음. 높이 때문이라는 이유가 빠짐 (p.15)",
   "rubric_scores": [3, 3, 2, 0]}
 ]}
```

객관식 문제(프롬프트 03-C 출력. 코드가 보기를 섞은 뒤 `kind`, `answer`를 채워 저장):

```json
{"question": "최대 힙에서 루트를 삭제한 뒤 힙 조건을 회복하는 과정으로 옳은 것은?",
 "choices": ["마지막 노드를 루트로 옮기고, 두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려간다",
             "마지막 노드를 루트로 옮기고, 왼쪽 자식과 비교해 작으면 교환하며 내려간다",
             "새 루트를 정하지 않고, 두 자식 중 더 큰 자식을 루트로 올린 뒤 그 자리를 비워 둔다",
             "마지막 노드를 루트로 옮기고, 부모와 비교해 크면 교환하며 올라간다"],
 "answer_index": 0,
 "explanation": "자료는 '두 자식 중 더 큰 자식과 비교해 작으면 교환하며 내려간다'고 설명한다(p.16). 부모와 비교하며 올라가는 것은 삽입 절차다.",
 "source_pages": [16]}
```

- 저장 형식(`Question`): `kind`("서술형"/"객관식"), `question`, `answer`(서술형: 모범 답안 / 객관식: 정답 보기 글), `rubric`(서술형만), `choices`, `answer_index`, `explanation`(객관식만), `source_pages`, `figure`(문제 그림, 없으면 null).
- `figure` 예: `{"kind": "tree", "nodes": ["+", "*", "-", "a", "b", "c", "d"], "caption": "수식 트리"}` / `{"kind": "array", "items": ["90", "75", "80"], "start": 1}` / `{"kind": "table", "header": ["연산", "시간 복잡도"], "rows": [["삽입", "O(log n)"]]}`
- `error_type`은 개념 혼동 / 비교 방향 오류 / 복잡도 오류 / 절차 누락 / 무응답 / 기타 / null. 객관식은 코드가 오답 / 찍어서 맞힘 / 무응답 / null로 적는다.
- `status`는 코드가 `score`로 다시 정한다. 8 이상 앎, 4\~7 헷갈림, 3 이하 모름.

### 6.6 우선순위 (priorities, 코드 출력)

```json
{"priorities": [
  {"concept_id": "c5", "name": "힙의 삭제 연산", "exam_pct": 97,
   "status": "모름", "understanding": 0.0, "priority": 97, "action": "지금 당장"},
  {"concept_id": "c1", "name": "힙의 삽입 연산", "exam_pct": 96,
   "status": "앎", "understanding": 1.0, "priority": 0, "action": "복습만"},
  {"concept_id": "c9", "name": "우선순위 큐", "exam_pct": 50,
   "status": "진단 안 함", "understanding": 0.5, "priority": 25, "action": "다음"}
 ]}
```

- `action`: priority 50 이상 "지금 당장", 20\~49 "다음", 20 미만 "복습만".

### 6.7 보완 설명 (explanations, AI 호출 4 출력)

```json
{"concept_id": "c5",
 "my_gap": "삭제를 삽입 절차(위로 올리기)와 혼동했다.",
 "explanation": "힙에서 최댓값을 삭제할 때는 루트를 꺼내고 마지막 노드를 루트로 올린 뒤 ‘자식 중 큰 쪽과 비교하며 아래로 내려간다’(p.17). ...",
 "check_pages": [17, 18],
 "source_pages": [17, 18],
 "not_found": false, "not_found_note": null,
 "confusion_reply": null}
```

- `not_found`가 true면 `not_found_note`에 "올린 자료에는 …에 대한 설명이 없음"을 적고, 화면에 배지로 보여준다.
- `source_pages`가 입력 페이지 밖이면 코드가 지운다.
- `confusion_reply`: S03에서 "확신 없이 골랐어요" 아래 칸에 학생이 적은 헷갈린 점에 대한 답(2\~4문장, p.n 인용). 적은 게 없으면 null (v1.4).

### 6.8 내보내기 HTML 구조 (파일 2개)

**① 공부 순서·오답노트** (`study_html`, `빈틈노트_공부순서_오답노트_<날짜>.html`)

1. 제목 "빈틈노트 공부 순서·오답노트", 아래 줄에 파일명 · 날짜 · 녹음/대본 포함 여부
2. 주의 문구 상자 + 숫자 칸 3개(지금 당장 · 다음 · 복습만)
3. **1. 공부 순서**: 단계별로 묶은 개념 줄(순위, 이름, 출제 가능성 막대, 우선순위 점수, 이해 상태 배지, 출제 근거 배지) + 계산식
4. **2. 오답노트**: 진단에서 모름·헷갈림인 개념을 공부 순서대로. 카드 한 장에 이름, 배지, 문제(그림 포함), (객관식) 보기와 정답·내 답 표시 또는 (서술형) 내 답, 채점 이유, 해설 또는 모범 답안, "보완 설명"(내가 놓친 점, 적었으면 내가 헷갈린 점과 그에 대한 답, 문단 설명과 p.n 배지, 찾지 못함 상자, 다시 볼 페이지). 설명이 없으면 근거 페이지만
5. **3. 맞힌 문제 · n개**: 같은 카드를 접어 둔다(눌러서 펼침)
6. **4. 진단하지 않은 개념 설명**: 진단하지 않은 개념에 만든 보완 설명이 있을 때만
7. 마지막 줄: "이 결과는 자료와 녹음의 신호를 규칙대로 더한 것으로, 실제 출제를 보장하지 않습니다."

**② 시험 대비 요약 노트** (`notes_html`, `빈틈노트_요약노트_<날짜>.html`)

1. 제목 "빈틈노트 시험 대비 요약 노트", 같은 정보 줄, 주의 문구 상자
2. 숫자 칸 3개(자세히 · 보통 · 짧게)
3. 강의 순서대로 개념마다 이름 + 자세한 정도, 배지, 요약 문단, 핵심, 자주 하는 실수, 교수님 말, 근거 페이지
4. 마지막 줄 주의 문구

두 파일 모두 원본 페이지 그림은 넣지 않는다.

### 6.9 시험 대비 요약 노트 (notes, AI 호출 5 출력)

```json
{"summary": "힙에 새 항목을 넣을 때는 '새 항목을 마지막 위치(배열의 끝)에 넣는다'(p.15).\n\n그 다음 '부모와 비교해 크면 교환'하며 루트 쪽으로 올라간다(p.15).",
 "key_points": ["삽입 = 끝에 넣고 부모와 비교하며 위로 (업힙)", "시간 복잡도 O(log n)"],
 "pitfalls": ["삭제(아래로 내려가며 더 큰 자식과 비교)와 방향을 혼동한다"],

```

- 저장 형식(`NoteSection`): 위 4개 + `concept_id`, `detail`("자세히"/"보통"/"짧게"), `from_ai`(짧게는 false).

## 7. AI 호출 설계

### 7.1 어떤 AI를 쓰나

| 역할 | 선택 | 이유 | 대안 |
| --- | --- | --- | --- |
| 언어 모델 (호출 1\~5) | Anthropic Claude `claude-sonnet-5-5` | 자료 40쪽을 한 번에 읽고 JSON 형식을 잘 지킨다. 입력 100만 토큰당 2달러, 출력 10달러. 3번 확인에서 같은 급 모델로 전 기능이 동작했다 | 비용·속도가 중요하면 `claude-haiku-5-5`(20배 저렴), 품질이 중요하면 `claude-opus-5-5`. 설정 한 줄 교체 |
| 음성 인식 (호출 0) | OpenAI 전사 API (`whisper-1` 또는 최신 전사 모델) | 한국어 강의 녹음을 파일 하나 보내면 글자로 돌려준다. 25MB 제한 | 키가 없으면 대본 붙여넣기만. 앱은 그래도 동작 |

필요한 키는 최대 2개(Anthropic, OpenAI)다. 둘 다 사용자가 발급한다. 두 번째 키를 빼고 싶으면 음성 인식을 끄고 대본 붙여넣기만 쓴다 (15장 미정 사항).

| --- | --- | --- | --- | --- | --- |

### 7.3 호출 방법 (모든 언어 모델 호출 공통)

- 함수 하나로 통일: `core/llm.py`의 `ask_json(prompt_text, max_tokens) -> dict`. 앱의 다른 코드는 이 함수만 부른다. 제공사를 바꾸고 싶으면 이 파일만 고친다.
- 공식 Python SDK(`anthropic`) 사용. 스트리밍으로 받아 긴 입력에서 시간 초과를 막는다. 호출 1, 2는 생각 모드(adaptive thinking)를 켜고, 3-A/3-B/3-C/4/5는 따로 켜지 않는다. 다만 `claude-sonnet-5-5`는 지정하지 않아도 스스로 생각할 수 있고 그 몫도 max\_tokens에 들어가므로 상한을 넉넉히 둔다.
- JSON 강제: 시스템 프롬프트에 "JSON만 출력" + SDK의 구조화 출력 옵션(JSON 스키마 지정)을 쓴다. 그래도 답에 글이 섞이면 코드가 첫 `{`부터 마지막 `}`까지만 잘라 파싱한다.
- 프롬프트 파일은 시작할 때 한 번 읽어 메모리에 두고, `{{MATERIAL}}` 같은 자리를 문자열 치환으로 채운다 (BR-10).
- max\_tokens: 호출 1은 8000, 2는 6000, 3-A/3-B/3-C/4는 4000(`AI_MAX_TOKENS`), 5는 5000(`NOTE_MAX_TOKENS`). 답이 상한에 걸려 잘려서(stop\_reason "max\_tokens") JSON을 읽지 못하면 상한을 두 배로(최대 16000) 늘려 한 번 더 받는다.
- 재시도: 네트워크 오류, 429, 5xx는 2초→4초 기다리고 최대 2회 더. JSON 파싱 실패는 같은 요청 1회 더. 그 뒤에는 E-07, E-08.
- 동시 호출: 3-A, 3-C, 3-B, 4, 5는 개념별로 독립이므로 스레드 6개로 동시에 부른다. 진단 개념이 많아도 대기 시간이 개수만큼 늘지 않는다. 한 개념이 실패해도 나머지는 그대로 쓰고, 실패한 것만 표시한다(9.1).
- 사용량 기록: 호출마다 입력·출력 토큰 수를 세션에 더해 S05에 "이번 분석 사용량"으로 보여준다. 동시 호출 묶음의 합을 세션에 더할 때도 호출 수는 묶음 안의 호출 수만큼 늘린다(`Usage.merge`). 저장된 결과를 다시 쓰면 더하지 않는다(v1.5).

### 7.4 설정 한 줄과 키 보관

`config.py` 전문:

```python
LLM_MODEL = "claude-sonnet-5-5"   # 이 한 줄만 바꾸면 모델 교체
STT_MODEL = "whisper-1"           # None이면 음성 인식 끄기(대본 붙여넣기만)
DIAG_MIN_PCT = 20                 # 출제 가능성 점수(0~100, 가장 높은 개념 = 100)가 이 값 이상인 개념은 전부 진단
ESSAY_MIN_PCT = 50                # "섞어서": 이 값 이상 서술형, 미만 객관식
MAX_PAGES = 120                   # 분석할 최대 쪽수
MAX_EVIDENCE_PAGES = 8            # 호출 3, 4, 5에 넣는 근거 쪽 상한
MAX_MATERIAL_MB = 30              # 강의자료 파일 크기 상한
MAX_AUDIO_MB = 25                 # 녹음 파일 크기 상한 (녹음 업로더별 상한으로도 건다, v1.5)
AUTO_EXPLAIN_TOP = 3              # S04에서 자동으로 설명을 만드는 상위 개수
AI_MAX_TOKENS = 4000              # 호출 3-A/3-B/3-C/4의 답 길이 상한
NOTE_MAX_TOKENS = 5000            # 호출 5(요약 노트)의 답 길이 상한
CONFUSION_MAX_CHARS = 300         # 헷갈린 점 입력칸 글자 수 상한 (v1.4)
MAX_ANALYSES_PER_SESSION = 5      # 세션당 분석 횟수. 0이면 제한 없음 (v1.5)
MAX_ANALYSES_PER_DAY = 150        # 서버 전체 하루 분석 횟수. 0이면 제한 없음 (v1.5)
QUICK_DIAG_TOP = 5                # "빠른 진단"을 켜면 출제 가능성 상위 몇 개만 (v1.5)
QUICK_DIAG_AUTO_OVER = 8          # 직접 올린 자료의 진단 대상이 이보다 많으면 빠른 진단 기본 켜짐 (샘플은 꺼짐, v1.12)
MAX_AI_CALLS_PER_DAY = 3000       # 서버 전체 하루 AI 호출 수. 0이면 제한 없음 (v1.12)
```

- 키가 없으면 앱 첫 화면에 E-06 안내를 보이고 분석 버튼을 잠근다. 샘플 체험 버튼도 키가 필요하다.

### 7.5 프롬프트 작성 규칙 (5번 완성 프롬프트에 반영)

1. 자료와 대본은 `<material>`, `<transcript>`, `<pages>` 같은 태그로 감싼다. 태그 안의 글은 데이터이고 지시가 아니라고 프롬프트에 명시한다(자료 안의 "이 페이지를 무시하라" 같은 문장에 속지 않게). 학생이 직접 적은 헷갈린 점도 student\_confusion 태그로 감싸 같은 규칙을 적용한다(v1.4).
2. 출력 예시 JSON을 프롬프트에 항상 넣는다.
3. "자료에 없는 내용을 만들지 마라", "인용은 그대로"를 모든 프롬프트에 넣는다.
4. 한국어로 쓴다. 필드 이름만 영문.
5. 버전은 파일명에 (`_v1`). 바꿀 때 새 파일을 만들고 `config.py`가 아니라 `core/prompts.py`의 파일명 표에서 고른다.

## 8. 점수와 우선순위 규칙

이 장은 코드가 그대로 구현하는 계산식이다. AI는 개입하지 않는다. 가중치는 3번 확인에서 샘플 정답표를 맞춘 v0 값이고, 7번 기출 비교 후 조정할 수 있다. 바꾸면 버전 번호를 올리고 README에 적는다.

### 8.1 출제 가능성 점수 가중치 (v0)

| 신호 | 어디서 오나 | 점수 | 비고 |
| --- | --- | --- | --- |
| 학습목표에 있음 | concepts.in\_objectives | +3.0 | 교수가 "이걸 배운다"고 쓴 것 |
| 본문 쪽수 | concepts.pages 중 메타 페이지 제외 | 쪽당 +1.0, 최대 4쪽(+4.0) | 오래 다룼 개념 |
| 예제·그림으로 과정 설명 | concepts.has\_example | +1.5 | 과정을 묻는 문제로 나오기 쉬움 |
| 연습문제에 포함 | concepts.has\_exercise | +2.0 | 개수와 무관하게 한 번만 |
| 강조 발화 | utterances type=emphasis | +1.0 × (strength/3), 발화마다 | 같은 말 2번이면 2번 |
| 시험 암시 | type=exam\_hint | +1.5 × (strength/3), 발화마다 | 가장 강한 신호 |
| 실수 경고 | type=mistake\_warning | +0.7 × (strength/3), 발화마다 |  |
| 연습문제 지목 | type=exercise\_hint (v1) | +1.0 × (strength/3), 발화마다 | "4번 꼭 풀어보세요" |
| 학우 질문 | type=question (F12, 선택) | +0.5, 질문마다 |  |
| 다음에 다룸 | type=deferral | −2.5, 발화마다 | "다음 주에 다시 봅니다" |
| 가볍게 넘어감 | type=skip | −1.0, 발화마다 | "참고만 하세요" |

### 8.2 계산 순서

1. 개념마다 위 표를 따라 더해 `raw`를 만든다. 근거 목록(`reasons`)에 항목마다 무엇이 몇 점인지 남긴다.
2. `raw`가 음수면 0으로 만든다.
3. 가장 큰 `raw`를 100으로 두고 나머지를 0~100 정수로 바꾼다 (`pct`). 모두 0이면 전부 0. 화면에는 "점"으로 보이고 %는 쓰지 않는다(확률이 아님, v1.7).
4. `pct` 내림차순, 같으면 본문 쪽수 많은 순, 그래도 같으면 등장 페이지가 앞인 순.
5. `concept_id`가 null인 발화는 점수에 넣지 않는다.

### 8.3 메타 페이지 판별

메타 페이지 = 아래 셋의 **합집합**이다(하나라도 해당하면 메타).
- AI 호출 1이 돌려준 `meta_pages`, `objectives_page`, `exercise_page`.
- 코드 규칙 ①: 페이지의 **첫 줄(빈 줄을 뺀 제목 줄)**이 "목차", "학습 목표", "학습목표", "연습문제", "연습 문제", "요약", "참고문헌", "차례"로 시작하면(앞의 절 번호 "8.6 "이나 기호는 무시). v1.12: 전에는 첫 80자 어디에든 있으면 메타로 봐서 "8.1 트리 요약하면 …"으로 시작하는 본문 쪽이 빠졌다.
- 코드 규칙 ②: 앞 12줄 중 3줄 이상이 "8.1 트리란?"처럼 절 번호 뒤에 공백과 제목 글자가 오는 줄이면(목차 쪽에 "목차"라는 글자가 없을 때를 잡는다. 샘플 p.2가 이 경우). 숫자만 늘어선 줄(예: "3.14 2.71")은 세지 않는다.
- 1쪽(표지)은 항상 메타.
- 본문 쪽수 = `pages`에서 메타 페이지를 뻐 개수.

### 8.4 계산 예시 (샘플 자료 + 저장된 AI 결과 `tests/fixtures/` 01·02로 코드가 계산한 값, T-01)

| 개념 | 더해지는 것 | raw | pct |
| --- | --- | --- | --- |
| 이진 트리의 순회 | 학습목표 3 + 본문 3쪽(p.8~10) 3 + 예제 1.5 + 연습문제 2 + 강조(강도 3) 1.0 + 시험 암시(강도 3) 1.5 + 시험 암시(강도 2) 1.0 | 13.0 | 100 |
| 힙의 삭제 연산 | 학습목표 3 + 본문 2쪽 2 + 예제 1.5 + 연습문제 2 + 강조 1.0 × 2회 + 시험 암시 1.5 + 실수 경고 0.7 | 12.7 | 98 |
| 힙의 삽입 연산 | 학습목표 3 + 본문 2쪽 2 + 예제 1.5 + 연습문제 2 + 강조 1.0 × 3회 + 시험 암시(강도 2) 1.0 | 12.5 | 96 |
| 이진 탐색 트리의 삭제 | 본문 1쪽 1 + 다음에 다룸 −2.5 × 3회 | −6.5 → 0 | 0 |

AI가 신호를 조금 다르게 찾으면(발화 수, 강도) 값도 조금 달라진다. 위 값은 저장된 결과 기준이다.

### 8.5 이해도 숫자화

| 진단 결과 | 조건 | 이해도 |
| --- | --- | --- |
| 앎 | 서술형 8\~10점 / 객관식 확신하고 맞힘(10점) | 1.0 |
| 헷갈림 | 서술형 4\~7점(틀린 유형이 "개념 혼동"이면 모름) / 객관식 "확신 없이 골랐어요"로 맞힘(5점) | 0.5 |
| 모름 | 서술형 0\~3점, 4\~7점이지만 "개념 혼동"(v1.12), 빈 답, "모르겠어요" / 객관식 틀림, "모르겠어요" | 0.0 |
| 진단 안 함 | 출제 점수 20점 미만이라 문제를 내지 않음 | 0.5 (모른다고 단정하지 않고 중간) |

객관식에서 "찍어서 맞힘"을 앎과 나누는 것이 메타인지 진단의 핵심이다. 맞힌 것과 아는 것은 다르다.

### 8.6 우선순위

- `priority = round(exam_pct × (1 − understanding))`. `round`는 파이썬 기본 동작(.5는 가까운 짝수 쪽: 48.5→48, 49.5→50)
- 내림차순. 같으면 exam\_pct 높은 순.
- 권장 행동: 50 이상 "지금 당장", 20\~49 "다음", 20 미만 "복습만".
- 앎으로 판정된 개념은 우선순위 0이 되어 맨 아래로 간다. 표에는 남긴다("잘 알고 있어요"를 보여주는 것도 가치).
- 진단 대상을 20점 이상으로 정한 이유: 우선순위는 출제 점수보다 클 수 없으므로, 출제 점수 20점 미만 개념은 진단 결과가 무엇이든 "복습만"이다. 결과가 바뀌지 않는 문제는 내지 않는다.

예: 힙 삭제(98점, 모름) → 98. 순회(100점, 헷갈림) → 50. 힙 삽입(96점, 앎) → 0. 우선순위 큐(50점, 진단 안 함) → 25.

### 8.7 조정 방법 (7번 기출 비교)

1. 사용자가 알려주는 실제 출제 개념 목록(1\~2과목)을 `tests/기출_개념표.json`에 적는다.
2. `python -m core.score --material ... --exam tests/기출_개념표.json`으로 "상위 10개 중 실제 출제 개수"를 출력한다.
3. 가중치를 한 개씩 바꿔 같은 숫자를 다시 본다. 좋아지면 v1으로 올리고, 아니면 v0 그대로.
4. README에는 측정한 숫자와 그 숫자를 낸 명령어를 같이 적는다. 측정하지 않은 숫자는 적지 않는다.

### 9.1 공통 원칙

- 한 단계가 실패해도 이미 성공한 단계의 결과는 세션에 남긴다. 다시 시도는 실패한 단계부터.
- 모든 예외는 `try/except`로 잡아 위 표의 문구로 바꾼다. 잡히지 않은 예외는 "알 수 없는 오류가 났어요. 처음부터 다시 해 주세요" + 펼침 상자에 예외 내용.
- 에러 문구에 API 키, 파일 경로, 서버 정보를 넣지 않는다.
- 실패한 AI 호출의 요청·응답은 세션의 `errors`에만 남기고 파일로 저장하지 않는다 (BR-06).
- AI 호출은 개념·문제마다 따로 실패를 잡는다. 하나가 실패해도 나머지 결과는 쓰고, 실패한 것만 표시해 버튼으로 다시 한다. 실패한 것을 자동으로 다시 부르지 않는다(비용).

### 10.3 파일 간 규칙

- `app.py`와 `screens/`는 `core/`를 부르기만 한다. `core/`는 Streamlit을 import하지 않는다. 그래야 화면 없이 테스트할 수 있다. 재배포 때 예전 모듈을 버리는 규칙(12.1)은 `screens.*`에도 똑같이 적용한다.
- AI를 부르는 파일은 `llm.py`와 `stt.py` 둘뿐이다.
- `score.py`, `priority.py`, `export.py`는 외부 호출이 없는 순수 함수. 같은 입력에 같은 출력.
- 실제 교재 PDF와 실제 녹음은 저장소 밖 `실제자료_비공개/`에만 둔다. `.gitignore`로 막고, 커밋 전에 `git status`로 확인한다.

### 11.3 테스트 데이터 규칙

- **가짜 AI 모드**: 환경변수 `BINTM_FAKE_AI=1`이면 `core/fake_ai.py`가 실제 AI 대신 답한다. 호출 1·2는 `tests/fixtures/`의 저장된 결과를, 호출 3~5는 정해진 모양의 답을 돌려준다. 키 없이 화면 확인, 스크린샷, 자동 테스트(`tests/conftest.py`가 켬)에 쓴다. 샘플 자료가 아니면 내용이 맞지 않는다.
- `tests/fixtures/`에는 가상 샘플의 결과만 넣는다. 실제 교재 내용이 들어간 JSON은 넣지 않는다.
- `신호표_정답.md`는 테스트 기대값의 출처이고, 앱이나 프롬프트에 입력으로 넣지 않는다.
- `기출_개념표.json`에는 "어떤 개념이 나왔다"만 적는다. 기출 문제 원문은 저장소에 넣지 않는다.

## 12. 배포

심사 AI가 누르면 바로 열리는 URL 하나와, 코드를 볼 수 있는 GitHub 저장소 하나가 필요하다.

### 12.1 순서

| 단계 | 누가 | 할 일 |
| --- | --- | --- |
| 1 | 사용자 | GitHub에 공개 저장소 만들고 팀원 초대 |
| 2 | 개발(AI/나) | 코드·프롬프트·샘플·README·테스트를 커밋. 커밋 전 `git status`로 비공개 자료와 secrets.toml이 없는지 확인 |
| 3 | 사용자 | share.streamlit.io에 GitHub으로 로그인 → New app → 저장소·브랜치 main·파일 app.py 선택 |
| 4 | 사용자 | 앱 설정 → Secrets에 아래 두 줄 붙여넣기. 이 Secrets는 배포 앱만 쓴다. 로컬 확인과 결과 예시(`scripts/make_example.py`)에는 작업 PC의 `.streamlit/secrets.toml`이 따로 있어야 한다(같은 키, v1.11) |
| 5 | 개발 | 배포 URL에서 A-07 확인, README 맨 위에 URL 기록 |
| 6 | 사용자 | 커밋할 때마다 자동 재배포되므로 따로 할 일 없음. 당일 마지막 커밋 후 URL 한 번 더 열어 확인 |

재배포 때 예전 모듈이 남는 문제(v1.6): Streamlit Cloud는 새 코드를 받아도 `app.py`만 다시 실행하고, 이미 불러온 `core.*`·`config` 모듈은 예전 것을 쓴다. 그러면 새로 추가한 함수나 설정을 못 찾아 ImportError가 난다. 그래서 `app.py` 맨 위(`core`·`config`를 import하기 전)에서 `_drop_stale_modules()`가 그 모듈 파일들의 수정 시각을 기록해 두고, 시각이 바뀌었으면 `sys.modules`에서 예전 모듈을 지워 새로 읽게 하고 서버 공용 캐시(`st.cache_resource`)도 비운다. 예전 모듈의 객체를 들고 있을 수 있기 때문이다. 프롬프트 파일(`prompts/*.md`)도 같은 방식으로 본다(v1.9). `core.prompts`가 프롬프트 글을 메모리에 들고 있고 샘플 진단 문제도 서버 공용 캐시에 있어서, 프롬프트만 바꾼 배포에서는 서버가 다시 켜질 때까지 예전 프롬프트가 쓰였기 때문이다. 프롬프트는 지난 기록에 없어도 바뀐 것으로 본다(이 기능이 들어간 첫 배포에서도 새로 읽게).

Secrets에 넣는 내용(키 값은 사용자만 가진다):

```toml
ANTHROPIC_API_KEY = "..."
OPENAI_API_KEY = "..."
```

### 12.2 무료 범위와 제한

- Streamlit Community Cloud 무료: 공개 저장소 앱, 메모리 약 1GB. 우리 앱은 파일 하나를 메모리에 들고 외부 API를 부르는 것뿐이라 충분하다.
- 일정 시간 접속이 없으면 앱이 잠든다. 다시 열면 수십 초 후 켜진다. 당일 심사 전에 한 번 열어두면 된다.
- API 비용은 사용자의 키로 나간다. 심사 AI가 여러 번 돌려도 한 번에 수백 원 수준(7.2). 키에 사용 한도를 걸어둔다(예: 월 1\~2만 원).
- 배포 앱은 운영자 키 하나로 모두가 함께 쓰므로 세션당 분석 5번, 서버 전체 하루 150번으로 제한한다(F14). 횟수는 서버 메모리에서 세므로 서버가 다시 켜지면 하루 횟수가 0부터 다시 센다. 키 한도는 AI 제공사 콘솔의 지출 한도로 함께 막는다.

- 앱을 한동안 아무도 쓰지 않으면 Streamlit이 앱을 재운다. 첫 화면이 "This app has gone to sleep"이 되고, **Yes, get this app back up!**을 누르면 30~38초 뒤 열린다. 깨어난 뒤 첫 분석은 저장된 결과가 없어 54.8~64.3초 걸린다(2026-11-09·10 측정). 제출 직전과 심사 시간대에 한 번 열어 깨워 두고, README에 깨우는 법을 적는다(v1.10).

### 12.3 배포가 안 될 때

- README에 로컬 실행법을 항상 적어 둔다: `pip install -r requirements.txt` → `.streamlit/secrets.toml` 만들기 → `streamlit run app.py`.
- 배포 실패 원인 대부분은 requirements 버전 충돌이다. 6번에서 배포를 미리 한 번 해봐서 당일에는 새 문제가 없게 한다.
- 정 안 되면 당일 노트북에서 로컬 실행 화면을 스크린샷으로 README에 넣고, README에 "배포 URL 대신 로컬 실행" 이유를 적는다.
