# 빈틈노트

강의자료와 교수님 강의 녹음 속 강조점, 메타인지 진단으로 시험 전 공부 우선순위를 정해 주는 AI 서비스입니다.

- 배포 URL: https://bintm-rehearsal-myagsiaqtsuzkjjrnnrpgc.streamlit.app
- 저장소: https://github.com/dodohun2212/bintm-rehearsal

> **출제를 보장하지 않습니다. 공부 우선순위를 정하는 참고용입니다.**

## 무엇을 하는 앱인가

강의자료(PDF/PPTX)와 교수님 강의 녹음(또는 받아쓴 대본)을 올리면 네 가지를 줍니다.

**① 출제 포인트 레이더**
- 자료에서 시험 문제 단위의 개념을 뽑고, 녹음에서 교수님의 강조·시험 암시·실수 경고·"다음 주에 다시"를 찾습니다.
- 신호를 정해진 가중치로 더해 가장 높은 개념을 100점으로 둔 비교용 출제 점수를 코드가 계산합니다(확률이 아닙니다).
- 개념마다 학습목표·본문 쪽수·예제·연습문제·교수님 말 같은 근거 배지와 원문 인용을 보여 줍니다.

**② 내 취약점 진단**
- 출제 점수 20점 이상인 개념 전부를 객관식·서술형 진단 문제로 확인합니다(빠른 진단을 켜면 상위 5개만).
- 객관식은 "확신 없이 골랐어요"를 체크하면 맞혀도 '헷갈림'으로 봅니다. 찍어서 맞힌 것과 아는 것을 나눕니다.
- 서술형은 AI가 루브릭으로 채점하고, 앎(8점 이상)·헷갈림(4~7)·모름(3 이하) 판정은 코드가 점수로 합니다.

**③ 우선순위 보완 학습 (오답노트)**
- 우선순위 = 출제 점수 × (1 − 이해도)로 "지금 당장 · 다음 · 복습만"을 정합니다.
- 개념마다 내 문제와 답, 채점, 정답, 자료 페이지를 인용한 보완 설명(p.n 배지)을 한 장에 담습니다. 자료에 없으면 "올린 자료에서 찾지 못함"으로 표시합니다.
- 찍으면서 적은 "헷갈린 점"에는 따로 답하고, 강의자료 원본 페이지 그림을 펼쳐 볼 수 있습니다.

**④ 시험 대비 요약 노트**
- 강의 순서대로 모든 개념을 정리합니다.
- '지금 당장'·출제 점수 50점 이상·진단에서 모른 개념은 자세히, '다음'·헷갈린 개념은 보통, 나머지는 한 줄로(이때는 AI를 부르지 않음).
- 공부 순서·오답노트와 요약 노트를 브라우저로 바로 열리는 HTML 파일 2개로 내려받습니다.

**결과 예시**: 앱을 열지 않고 결과를 읽으려면 [docs/결과_예시/README.md](docs/결과_예시/README.md)를 보세요. 배포 앱에서 샘플로 한 바퀴 돌려 내려받은 HTML 2개와, 같은 내용을 GitHub에서 읽기 좋게 바꾼 마크다운 2개가 있습니다.

## 사용 방법

앱이 잠들어 있으면 "This app has gone to sleep" 화면이 나옵니다. **Yes, get this app back up!**을 누르고 30초쯤 기다리면 열립니다.

1. **샘플로 체험**: 첫 화면의 "🧪 샘플로 체험"을 누르면 우리가 만든 가상 강의자료(자료구조 8장 트리와 힙, 20쪽)와 녹음 대본으로 바로 분석합니다. ②에서 "n개 개념 진단하기" → ③에서 문제를 다 풀 시간이 없으면 **"예시 답 채우기 (샘플 체험용)"** → "채점하기" → "공부 순서 보기" 순서로 끝까지 볼 수 있습니다.
2. **내 자료 올리기**: PDF나 PPTX(최대 30MB)를 올리고 "분석 시작". 녹음이 없어도 됩니다(녹음 신호만 0).
3. **녹음 대신 대본 붙여넣기**: 휴대폰 녹음 앱의 받아쓰기나 클로바노트 등으로 받아쓴 글을 "대본 붙여넣기" 탭에 넣습니다. 녹음 파일(m4a/mp3/wav, 최대 25MB)은 OpenAI 전사 API로 받아씁니다.
4. **빠른 진단**: 진단할 개념이 5개보다 많으면 ②에서 "빠른 진단: 출제 가능성 상위 5개만 풀기"를 켤 수 있습니다. 나머지는 '진단 안 함'(이해도 0.5)으로 계산합니다.
5. **분석 횟수 제한**: 배포 앱은 운영자 키 하나로 모두가 쓰므로 "분석 시작"·"샘플로 체험"을 화면(세션)당 5번, 서버 전체 하루 150번까지 셉니다. 실패한 분석은 세지 않습니다. 샘플 자료의 진단 문제는 한 번 만들면 다음 사람에게도 그대로 냅니다.

## 어떻게 동작하나

**AI는 읽고 분류하고 설명만, 점수·순위·이해 상태 판정은 코드가 합니다.** 그래서 AI가 찾은 신호가 같으면 항상 같은 점수가 나옵니다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 추출·마스킹 | 코드 | PDF(PyMuPDF)/PPTX(python-pptx) 페이지별 텍스트. 학번·전화번호·이메일을 `[마스킹]`으로(자료와 대본 모두) |
| 호출 1 개념 추출 | AI | 자료 전체 → 개념 목록·메타 페이지 (`prompts/01_개념추출_v1.md`) |
| 호출 2 강조 발화 | AI | 대본 + 개념 목록 → 교수님 발화. 대본에 실제로 있는 문장만 남김 (`02`) |
| 출제 점수 | 코드 | 아래 가중치 표 (`core/score.py`) |
| 호출 3-A/3-C 진단 문제 | AI | 그 개념의 근거 페이지만(최대 8쪽) → 서술형/객관식. 트리·배열·표는 데이터로 받아 코드가 그림 (`03A`, `03C`) |
| 호출 3-B 서술형 채점 | AI | 루브릭 채점. 객관식과 "모르겠어요"는 코드가 채점 (`03B`) |
| 우선순위 | 코드 | `priority = round(출제 점수 × (1 − 이해도))` (`core/priority.py`) |
| 호출 4 보완 설명 | AI | 진단 결과 + 헷갈린 점 + 근거 페이지 → p.n 인용 설명 (`04`) |
| 호출 5 요약 노트 | AI | 자세히·보통 개념만 (`05`) |

출제 가능성 점수 가중치 v0 (`core/score.py` 맨 위 표 하나):

| 신호 | 점수 |
|---|---|
| 학습목표에 있음 | +3.0 |
| 본문 쪽수(메타 페이지 제외) | 쪽당 +1.0, 최대 +4.0 |
| 예제·그림으로 과정 설명 | +1.5 |
| 연습문제에 포함 | +2.0 |
| 강조 발화 | +1.0 × (강도/3), 발화마다 |
| 시험 암시 | +1.5 × (강도/3), 발화마다 |
| 실수 경고 | +0.7 × (강도/3), 발화마다 |
| 연습문제 지목 | +1.0 × (강도/3), 발화마다 |
| 다음에 다룸 | −2.5, 발화마다 |
| 가볍게 넘어감 | −1.0, 발화마다 |

음수는 0으로 자르고, 가장 큰 값을 100점으로 둡니다. 이해도는 앎 1.0 · 헷갈림 0.5 · 모름 0.0 · 진단 안 함 0.5, 우선순위 50 이상 "지금 당장", 20~49 "다음", 20 미만 "복습만"입니다.

**모델**: 언어 모델은 Anthropic `claude-sonnet-5-5`(공식 Python SDK, 스트리밍, 호출 1·2는 adaptive thinking), 음성 인식은 OpenAI `whisper-1`입니다. 모델 이름은 `config.py`의 `LLM_MODEL` 한 줄에만 있고, 그 줄만 바꾸면 교체됩니다. 모든 언어 모델 호출은 `core/llm.py`의 `ask_json()` 하나를 거치고, 답은 JSON으로 파싱해 pydantic 형식과 값 범위를 코드가 검사합니다.

## 로컬 실행

```bash
python -m pip install -r requirements.txt
```

`.streamlit/secrets.toml`을 만들고 키 이름에 값을 적습니다(이 파일은 `.gitignore`에 있어 커밋되지 않습니다).

```toml
ANTHROPIC_API_KEY = "..."
OPENAI_API_KEY = "..."   # 녹음 받아쓰기를 쓸 때만
```

```bash
python -m streamlit run app.py
```

키 없이 화면만 보려면 `BINTM_FAKE_AI=1`(가짜 AI 모드: 저장된 결과와 정해진 답)을 켭니다.

## 한계와 향후 계획

- 스캔 PDF(글자가 그림인 PDF)는 읽지 못합니다(E-03 안내). 글자 인식은 향후 계획입니다.
- 한 번에 강의 한 장(chapter)을 전제로 합니다. 120쪽이 넘으면 앞 120쪽만 분석합니다.
- 녹음은 25MB까지입니다. 길면 대본 붙여넣기를 씁니다.
- 출제 점수는 규칙 기반 추정입니다. 가중치 v0는 샘플 자료의 정답표에 맞춘 값이고, 실제 기출과 비교하는 스크립트(`scripts/compare_exam.py`)가 있지만 아직 기출로 잰 값은 없습니다.
- 분석 횟수는 서버 메모리에서 세므로 서버가 다시 켜지면 하루 횟수가 0부터 다시 셉니다.
- 다른 모델로 바꾸면 `config.py` 한 줄이면 되지만, 바꾼 모델로 다시 재 보지 않은 숫자는 적지 않았습니다.
- 수업 중 학우 질문을 신호로 넣는 기능(F12)은 넣지 않았습니다.

## 데이터 처리·저작권·녹음 동의

- 올린 자료와 녹음은 분석을 위해 AI 제공사(Anthropic, OpenAI) 서버로 전송됩니다. 학번·전화번호·이메일은 보내기 전에 가립니다(사람 이름은 건드리지 않음).
- 올린 파일은 서버 디스크에 저장하지 않습니다. 결과는 브라우저 화면(세션)에 두고, 같은 파일을 다시 분석할 때를 위해 개념·강조 분석 결과와 쪽 그림은 서버 메모리 캐시에, 샘플 자료의 진단 문제는 서버 공용 메모리에 둡니다. 서버가 다시 켜지면 사라집니다. 녹음은 파일로 쓰지 않고 바로 전사 API로 보냅니다.
- 저장소에는 우리가 직접 만든 가상 샘플(`samples/`)만 있습니다. 교재 PDF·실제 녹음·기출 원문은 넣지 않습니다.
- 녹음은 교수님 허락을 받은 것만, 개인 학습 목적으로만 올려 주세요. 녹음을 공유하거나 저장하는 기능은 없습니다.
- API 키는 `st.secrets` → 환경변수 순으로만 읽고, 코드·저장소에 넣지 않습니다.
